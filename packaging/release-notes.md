Lanwork __VERSION__

## 更新

自 v0.4.0 以来。

### 应用页

面板标签现在是待办、便签、收纳、应用、设置。没有「扩展」标签。设置里不另设「应用」页。

应用页把已安装的工具排成一列，最后一张是「导入+」。不分成「内置」和「自定义」。没有番茄钟。配置里以前留下的番茄钟分钟数，打开时忽略，保存时不再写回去。没有工具时只显示「导入+」，不显示「没有工具」。

每张卡片有图标、名称、一行短说明、「悬浮窗」、启用开关和「⋯」。「⋯」里是「更新」「卸载」「查看权限」。清单里声明了密钥时，再加「填写密钥」。有 `icon.png` 时用这张图；没有、读不出或不是 PNG 时，用名称的第一个字。

关掉启用开关会马上关掉这个工具的悬浮窗，重启后仍是关闭。开关关闭时「悬浮窗」点不了。已经打开时再点，只把焦点给这一个窗口。新导入的工具默认启用。

### 导入、确认和卸载

「导入+」可以选择一个文件夹或一个 zip，也可以把它们拖到应用页上。先看到工具名称、一行短说明，以及要授予的权限。整份接受才安装，不能只勾其中几条。取消则不安装，原来的文件夹还在。

确认页按白话列出：定时刷新、发送通知、保存这个工具自己的数据、读取待办、完成待办，以及每个网站的「访问 <主机名>」。清单允许向这些网站提交数据时，每个主机再加一句「向 <主机> 提交数据」。有固定请求头时，每一条写成「请求头 名称: 值」。有密钥时能看到请求头的名字和前缀，看不到值。有登录描述时能看到要读的文件、发往的地址、请求头，以及交给脚本的字段名。

同一 id 再导入是更新。确认页写「保留数据」。确认后换成新副本，这个工具已有的存储、密钥、窗口位置、大小、贴边和钉住还在。悬浮窗如果开着，就在原来的位置用新副本重载。从某一张卡片的「更新」选到另一个 id 时，显示「不是这个工具的更新包」，不继续导入。「导入+」和拖入不受这一条限制。

卸载要先确认。确认框写「会删除这个工具的存储和密钥。」确认后关掉悬浮窗，并删除副本、存储、密钥和窗口记录。

id 以 `lanwork.` 开头的不安装，显示「清单无效」。清单里写了 `usage` 同样不安装，也是「清单无效」。

### 工具悬浮窗

工具的窗口是一块外壳。顶部可以拖动，右侧是钉住和关闭。钉住开着时在其他普通窗口之上，关掉时是普通窗口；没有记下时按开着。可以贴边收成把手，规则和便签悬浮窗相同。不画来源行，也不和便签、收纳、待办叠在一起。

位置、大小、贴边和钉住会记住。关闭后再打开、重启后再打开，用记下的值。退出时开着、并且启用开关开着的窗口，下次启动再打开。没有记下位置时，出现在主屏幕工作区的右下角。关闭窗口只关窗口，不卸载工具。面板收起时这个窗口不关闭。

里面的内容由工具自己的清单画出，逻辑在沙箱里的 Lua 中运行。脚本不能读工具文件夹以外的文件，也不能启动进程。一次调用超过 1 秒，窗口显示「脚本超时（第 N 行）」；脚本出错显示「脚本错误（第 N 行）」。

工具可以定时刷新、发系统通知、保存自己的文本、读取待办，以及完成待办。完成走现有的完成；和本机同时在改同一条时不覆盖，窗口显示「待办保存冲突」。这一批不能新建或修改待办和便签，也不碰收纳。通知在安静时段内不弹出。

### 联网、密钥和提交数据

请求只发往清单里写明、并且已经确认的主机名。可以发 https 的 GET。清单允许提交时，还可以向这些主机 POST JSON。没允许的 POST 不发出，显示「不在范围内」。不跟随重定向。不附带密钥的明文 http 不发送。附带密钥的请求只走 https。

一次请求可以带上多个已填写的密钥，最多 8 个。每个密钥进清单里为它写死的那一个请求头，前缀也以清单为准。还没填写就带上这个密钥时，整次都不发，显示「未填写密钥」。

「填写密钥」在卡片的「⋯」里。每一行是掩码输入，不回显已经保存的值，关掉再打开是空的。保存写入 Windows 凭据管理器；空着的行保持原样。某一行没有写上时提示「「名称」没有写下」，已经写上的行仍然生效。清除会删掉这个工具已声明的密钥。保存或清除之后，已经打开的窗口用上新的值。脚本读不到密钥原文。密钥不进入导出和备份。

固定请求头写在清单里，不由脚本临时添加。确认页能看到名称和值。不要把密钥写在固定请求头里。

### 登录描述

宿主不再内置 ChatGPT、Claude 或 Grok 的用量来源。工具要在清单里自己写 `[[login]]`：本机登录文件、放进哪个请求头、怎样判断过期、向哪个地址发什么请求，以及把响应里的哪些字段交给脚本。脚本只拿到点名的字段，拿不到令牌和原始正文。宿主只读这些文件，不修改。

仓库里有三个可以导入的示例，窗口里显示已用百分数和重置时刻。它们不在安装包里：

- [chatgpt-usage](https://github.com/wynxing/Lanwork/tree/__TAG__/examples/chatgpt-usage)：读 `~/.codex/auth.json`，向 `chatgpt.com` 查询 5 小时和每周用量。有套餐类型时写在第一行前面。
- [claude-usage](https://github.com/wynxing/Lanwork/tree/__TAG__/examples/claude-usage)：读 `~/.claude/.credentials.json`，向 `api.anthropic.com` 查询 5 小时和 7 天用量。Anthropic 的条款把订阅令牌限制在 Claude Code 和 claude.ai，使用这个示例由用户自行承担风险。
- [grok-usage](https://github.com/wynxing/Lanwork/tree/__TAG__/examples/grok-usage)：读 `~/.grok/auth.json`，按清单里的 `https://auth.x.ai` 选出登录项，向 `cli-chat-proxy.grok.com` 查询额度。过期时间按毫秒。本机文件的前缀或时间格式不同时，要改清单里的对应写法，否则窗口是「登录已过期」。

以前从旧的 ChatGPT 示例导入的工具，清单里写的是内置 `usage`，id 是 `example.chatgpt-usage`。这一版打开它显示「清单无效」。需要从上面的新示例再导入一次。id 没有变，再导入是更新；确认之后，已有的存储和窗口位置还在。

仓库的 `examples/` 里还有离线的倒计时，以及一个向占位主机 `api.example.com` 查询额度的示例。

### 外部 AI

设置的「其他」里有一项「外部 AI」，默认关闭。打开后只在本机 `127.0.0.1` 的端口 `39217` 上接受连接，地址是 `http://127.0.0.1:39217/mcp`。刚打开开关却绑定失败时，开关回到关，这一行显示「无法监听」。启动时文件里已经是开的、但绑定失败，开关保持开，同样显示「无法监听」。

名称框和「授权」并排。填上客户端名称后点「授权」，token 原文只出现这一次，旁边是上面的地址。磁盘上只保存哈希。每一行是客户端名称、「已连接」或「未连接」，以及「撤销」。没有客户端时显示「没有客户端」。撤销之后，原来的 token 不能再改数据。关掉开关后，新的调用不写盘。

已授权的客户端可以读取、新建、修改、完成、取消完成、软删除和恢复待办和便签。删除进回收站，不能永久删除，也不改收纳、搜索、配置和备份。搜索框仍然只参与搜索。外部修改不加标记。

和本机同时改同一条待办时不覆盖。待办页出现「待办保存冲突」，可以选择「保留本机的版本」或「保留外部的版本」。关掉开关或撤销之后，已经出现的「保留外部的版本」仍可以写入。便签仍按原来的方式处理同时修改。

授权记在数据目录的 `external-ai.json`。这份文件不进入导出和备份，更换数据目录时也不复制。换过目录之后需要重新授权。

### 退出

托盘「退出」和系统结束会话都会先保存还没写入的便签。界面正忙、暂时读不到这些窗口时，不结束进程，稍后重试，也不把这次当成保存失败。大约两秒仍退不出时，显示「还有便签没保存好，暂时无法退出」和原因。保存失败时停在便签窗口，可以选择重试或放弃修改。放弃或保存成功之后才继续退出。未保存的修改不会被丢掉。

### 备份、导出与导入里的工具

导出、自动备份和手动备份会带上已安装的工具副本、工具自己的存储、启用状态，以及窗口的位置、大小、贴边和钉住。密钥不在里面。

恢复或导入之前，概览在待办、便签、收纳下面列出每个工具的名称和权限，句子和导入确认相同。确认后才写入，授权按清单重新生成。不合格的写「不会恢复」和原因，本机原来的那一份留下。取消则什么都不写。换一台机器恢复之后，窗口上是「未填写密钥」。入口脚本和清单与本机这份相同的，本机密钥仍在。

更换数据目录会把这些工具文件一起复制过去，不另做这次确认。密钥在凭据管理器里，不跟着复制。

## 安装版

主要下载：`Lanwork-Setup-__VERSION__.exe`

按当前用户安装，不需要管理员权限。不安装 WebView2，也不安装 Windows App Runtime。开始菜单里的 Lanwork 快捷方式带通知用的 AppUserModelID 和激活 CLSID。卸载会去掉这些注册项，以及开机启动里名为 Lanwork 的项，不会删除文档中的 Lanwork 数据目录。

## 便携版

附加下载：`Lanwork-__VERSION__-portable-x64.zip`

压缩包里是同一套程序文件，不含安装程序。
