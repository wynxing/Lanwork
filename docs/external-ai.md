# 外部 AI（本机 MCP）

本文规定外部 AI 通过本机 MCP 修改待办和便签时的可见行为，以及工具、数据形状、错误和安全模型。与 [product.md](product.md) 已经写明的规则冲突时，以 product.md 为准。写入走现有的待办命令和便签命令。实现排在 v0.2.0 之后，状态见 [roadmap.md](roadmap.md)。已有代码，未在 Windows 上验收。技术验证表里还没有通过记录。设置里的开关和待办页上的选择提示已按本文写上。

搜索框里的字符只参与搜索。外部创建只走下面的工具，不改「快速收集」的前缀规则。

## 设置

**入口。** 设置。

**可见内容。** 一项开关，名称「外部 AI」，默认关。开着时，下面列出已授权的客户端。每一行是客户端名称、是否已连接，以及「撤销」。没有客户端时只显示「没有客户端」。文件里开关是开的、但没有在听时，这一行显示「无法监听」。

**动作。**

| 动作 | 结果 |
| --- | --- |
| 打开开关 | 开始在本机接受连接。绑定失败时开关回到关，并显示「无法监听」 |
| 关掉开关 | 不再接受新连接。已经连上的会话断开 |
| 启动时文件里开关是开的，但绑定失败 | 文件里的开关保持开，下次启动再试。设置这一行显示「无法监听」 |
| 授权 | 用户在设置里明确授权一个客户端，得到单独的一把 token |
| 撤销 | 该 token 立即失效。之后的调用不写盘 |

授权完成时，token 原文只出现一次。磁盘上只保存哈希。原文如何交到外部工具，待定。客户端列表除名称、是否已连接和「撤销」之外，是否显示最近一次调用的时间，待定。

「已连接」表示这个客户端持有还没结束的会话，并且最近 60 秒里有过请求，或者这次调用还在进行。删除会话，或连续 60 秒没有请求，这一行回到「未连接」。设置页开着时这一行自己刷新，不必再等下一次调用。过期的会话不能再调用，需要重新 `initialize`。同时有 16 个连接时，再来的连接得到 HTTP 503，正文是「连接过多」，不写盘。同时最多有 4 个这样的拒绝在进行；再多的连接直接丢掉，不回答。每一次拒绝从写出到排空请求共用 5 秒，到点就结束，这 4 个位置会空出来。

**禁止。** 默认把开关打开。外部工具已安装就自动授权。把 token 原文写进界面说明、导出、备份或日志。

**验收。** 新安装时开关是关的，本机没有监听。打开后，没有 token 的调用不改变待办和便签。撤销后再用原来的 token 调用，数据不变。关掉开关后，新的调用不写盘。

## 同时修改

外部工具和本机用户同时修改同一条待办时，不直接覆盖。本机对这条还有未写盘的修改，包括正在输入、输入法组合，以及某一次向前替换正式文件之前才变成未写盘的那一下，都视为同时修改。工具返回「待办保存冲突」，并带上 id。每一次向前替换之前再看一次。未写盘的修改在这一步出现，就丢掉这次替换。一次写入要换多个文件时，后面的文件被丢掉，前面已经换过的文件写回这次写入之前的字节；这次写回，以及写回失败后的修复，不再做这道检查。做完之后，磁盘上的文件与这次写入之前相同，待办服务仍然装着这些清单。已打开的编辑区如果这条还有未写盘的修改，刷新时不用磁盘上的新值盖住输入框里的草稿。

待办页在到期、提醒、周期的下方留出一条，不盖住这些字段。文字是「待办保存冲突」，后面是这次等待的客户端名称和当前磁盘上的标题，颜色与便签冲突条相同。选项只有「保留本机的版本」和「保留外部的版本」。

读取待办时带 `revision`。`update_todo`、`complete_todo`、`uncomplete_todo`、`delete_todo`、`restore_todo` 必须带回这次读到的 `revision`。它与当前已保存的修订号不一致，或者本机对这条还有未写盘的修改，就视为同时修改。

同一条已经有一条还没选定的外部提交时，后来的外部提交不替换它，仍然返回「待办保存冲突」，不写盘。条上的名称是先到的那个客户端。

选定之前，本机之后的成功保存照常写盘，不取消这条等待。编辑区显示刚保存的本机内容。条还在，名称仍是先到的客户端，标题改成这次保存之后磁盘上的标题。选择「保留外部的版本」时，写入的是先到的那一份外部字段；外部省略的字段用按下按钮时磁盘上的值，包括这段时间本机保存过的内容。选择「保留本机的版本」时，丢掉外部提交，磁盘保持最近一次本机保存。

用户选择「保留本机的版本」后，外部这次提交丢弃。选择「保留外部的版本」后，才写入外部提交的字段。还没选定的外部内容只留在本进程内存里。进程退出后丢弃，不写盘。关掉开关或撤销 token 之后，这条已经拿在手里的提交仍可以选择「保留外部的版本」。那是用户自己的选择，不要求开关还开着，也不要求这把 token 还有效。

旧的待办文件没有 `revision` 时按 0 读取。成功写入后修订号加一。界面不单独展示这个数字。待办和便签上都不因外部修改而多一个标记。

便签仍按产品规格「便签」处理同时修改：后保存的一方选择保留哪个版本。修订号冲突时不覆盖。

## 删除与恢复

外部工具的删除是软删除，进入现有回收站。保留 30 天、恢复、永久删除，以及原清单已删除时回到默认清单，都按 [product.md](product.md)「待办」和「便签」。永久删除不提供给外部工具。恢复可以由外部工具调用，也可以由用户在回收站里做。

## 工具

提供工具调用。资源、提示词和采样不在这个接口里。协议修订版本，待定。

传输是只监听本机回环的 HTTP，还是由外部工具以标准输入输出拉起，待定。两种都只接受本机连接。

调用进入与界面相同的待办命令和便签命令。完成、取消完成、周期和回收站按已有规则。待办与本机同时修改时按「同时修改」，不直接覆盖。便签修订号冲突时不覆盖。

| 工具 | 作用 |
| --- | --- |
| `list_lists` | 读取清单的 id、名称和种类 |
| `list_todos` | 读取待办。默认不含回收站 |
| `get_todo` | 按 id 读取一条。回收站里的也能读到 |
| `create_todo` | 新建一条。未指定清单时放进收件箱 |
| `update_todo` | 修改已有条目里允许的字段 |
| `complete_todo` | 完成。带周期的按产品规格生成下一次 |
| `uncomplete_todo` | 取消完成。产品规格里仍待定的分支保持待定 |
| `delete_todo` | 软删除，进入回收站 |
| `restore_todo` | 从回收站恢复 |
| `list_notes` | 读取便签。默认不含回收站 |
| `get_note` | 按 id 读取一篇，含正文和修订号。回收站里的也能读到 |
| `create_note` | 新建一篇 |
| `update_note` | 按修订号保存。冲突时不覆盖 |
| `delete_note` | 软删除，进入回收站 |
| `restore_note` | 从回收站恢复 |

第一批不提供：永久删除、设为当前、清除当前、处理模式、收纳、文件、搜索、启动应用、配置、备份、热键、通知注册。以后是否对外部工具开放设为当前和清除当前，待定。

清单的新建、改名和删除是否进入第一批，待定。`list_lists` 只读。收件箱不能删除，这条已有规则保持不变。

`list_todos` 可以按清单筛选，也可以要求包含回收站。`list_notes` 同样可以要求包含回收站。一次调用返回全部匹配条目。条数上限，待定。

`update_todo` 里省略的字段保持原值。到期日、提醒或周期要清空时，该字段传 `null`。

## 数据形状

字段名用 camelCase，与现有 JSON 相同。时间是 Unix 纪元起的 UTC 毫秒。日期是 `YYYY-MM-DD`。提醒是 `HH:MM`。id 沿用现有的文件名分量规则。

### 待办

`create_todo` 与 `update_todo` 使用这些字段：

| 字段 | 含义 |
| --- | --- |
| `id` | 读取、修改、完成、删除、恢复时必填。新建时由程序分配 |
| `listId` | 清单 id。新建时可以省略，省略则放入收件箱 |
| `title` | 标题。新建必填。去掉首尾空白后为空则拒绝 |
| `due` | 到期日。可以省略，也可以是 `null` |
| `remindAt` | 提醒时刻。可以省略，也可以是 `null` |
| `recurrence` | 周期。`rule` 为 `daily`、`weekly`、`biweekly`、`monthly`。`until` 是重复截止日。`monthDay` 是每月要回到的日子。可以省略，也可以是 `null` |
| `completed` | 只在读取时出现。完成和取消完成走各自的工具 |
| `revision` | 读取时返回。修改、完成、取消完成、软删除和恢复时必填，必须是这次读到的修订号 |

读取时另外返回 `listId`、`order`，以及 `deletedAt`（不在回收站则没有这个字段）。来源 `source` 只读，已有记录按原样返回。外部工具是否可以写入 `http` / `https` 来源，待定。

这些工具不读写 `movedAt`、`currentSince`、`generatedNext`、`everCompleted`、`generatedUntouched`、`originListId`。当前标记 `current` 不在第一批。成功写入不另加外部来源标记。

### 便签

| 字段 | 含义 |
| --- | --- |
| `id` | 程序分配。修改、删除、恢复时必填 |
| `title` | 按原文保存。没有非空白字符时，界面仍显示「无标题」 |
| `body` | 正文 |
| `tags` | 字符串列表。去掉首尾空白、丢掉空标签、按原文去重，与现有便签相同 |
| `pinned` | 列表里的置顶 |
| `revision` | 修改时必填，必须是读取到的修订号。成功后返回新的修订号 |
| `createdAt` | 只读 |
| `updatedAt` | 只读 |
| `deletedAt` | 只读。不在回收站则没有 |

这些工具不读写 `floatWindow`、`floatDock`、`floatStack`，也不读写待办悬浮窗的 `todo-float.json`。悬浮位置仍只由界面记录。成功写入不另加外部来源标记。

### 客户端

授权记录在数据目录的单独文件里，不在 `config.json`。`schemaVersion` 为 1。每条有 `id`、`name`、token 的哈希、`createdAt`。撤销之后该条不再接受调用。文件名，待定。这份文件不进入导出包，也不进入备份，也不随更换数据目录复制。目标目录里只有这份文件时，视为已有 Lanwork 数据，不合并，文件留在原地。更换成功后，当前进程丢掉内存里的 token 和会话，按新目录重新读取授权。新目录没有这份文件时开关是关的，需要重新授权。导出不含 token。

## 错误

工具失败时返回错误。错误里不包含便签正文，也不包含 token。写盘失败时原文件保留，不发布变更。一次调用只做这一次命令。失败则这一次没有写入。

界面文字仍只允许名称、数量、时间、状态和错误。

| 情况 | 结果 |
| --- | --- |
| 开关关闭 | 不监听。没有调用发生 |
| token 缺失、不正确或已撤销 | 「未授权」。不写盘 |
| 调用了第一批没有的能力 | 「不在范围内」。不写盘 |
| 标题为空 | 「标题为空」。不写盘 |
| 找不到待办或便签 | 沿用「找不到待办」或「找不到便签」，并带上 id |
| 待办已经在回收站时再删除 | 「待办已经在回收站」。不写盘 |
| 便签已经在回收站时再删除 | 「便签已在回收站」，并带上 id。不写盘 |
| 不在回收站时恢复 | 沿用「待办不在回收站」或「便签不在回收站」 |
| 便签修订号与磁盘不一致 | 「便签保存冲突」，并带上 id。不覆盖 |
| 待办与本机同时修改 | 「待办保存冲突」，并带上 id。不覆盖。待办页提示用户选择保留哪一版 |
| 提醒时刻无效 | 「提醒时间无效」 |
| 每月重复的日子不是 31，而目标月没有这一天 | 沿用现有拒绝，不落盘。落到哪一天仍按产品规格待定 |
| 参数无法解析 | 「参数无效」。不写盘 |
| 写盘失败 | 原文件保留。工具返回存储错误。已打开的窗口不收到这次变更 |

外部写入失败时，工具返回错误。面板上是否再显示同一条错误，待定。待办保存冲突的选择提示按「同时修改」，不在此列。

调用频率上限，待定。监听用的端口或管道名，以及重启后是否沿用，待定。关掉开关时，已经开始的那一次调用是做完还是中止，待定。是否同时接受 IPv6 回环，待定。

## 安全模型

1. 默认关闭。设置里没有打开时，不监听，也不接受标准输入输出会话。
2. 只接受来自本机的连接。监听地址只用 IPv4 回环 `127.0.0.1`。不绑定 `0.0.0.0`，也不绑定局域网地址。是否同时接受 IPv6 回环 `::1`，待定。
3. 每个客户端单独一把 token。没有 token 就不能调用工具。一把 token 不能代替另一把。
4. 授权和撤销都在设置里，由用户做出。
5. 磁盘上保存 token 的哈希，不保存原文。日志不写 token 原文，沿用现有日志对密钥形态的删节。
6. 授权记录不进入导出，也不进入备份。
7. 第一批工具只覆盖待办和便签的增删改查，以及完成、取消完成和从回收站恢复。收纳分组、路径引用、文件内容、应用索引、配置、备份、环境变量和日志都不读取、不修改。
8. 写入走现有命令。非法输入不写盘。单进程、单写者，与架构文档相同。
9. 删除只进回收站。永久删除仍只在回收站里由用户做出。
10. 这个接口只接受来自本机的连接。

## 禁止

- 用搜索框里的文字创建待办或便签。
- 永久删除。
- 读取或修改收纳、文件、配置和备份。
- 把 token 放进导出包。
- 为外部修改在待办或便签上加标记。

## 验收

开关默认关闭，此时待办和便签不能被外部工具改动。打开并授权一个客户端后，该客户端可以新建、修改、完成、软删除和恢复待办，以及新建、修改、软删除和恢复便签。另一把 token，或已经撤销的 token，做不到这些。软删除的条目出现在回收站，用户可以恢复。收纳分组和其中的路径在这些调用之后不变。导出的包里没有 token 原文，也没有授权文件。待办和便签上没有因外部修改而多出来的标记。

本机正在改一条待办时，外部工具再改同一条：磁盘内容不变，待办页出现「保留本机的版本」和「保留外部的版本」，并写出等待的客户端名称。选定之前没有写入外部的那一版。选择「保留本机的版本」后，外部提交不留下。选择「保留外部的版本」后，写入的是外部提交的字段。这条提示还在时本机再保存，磁盘换成这次本机保存，提示仍在，名称仍是先到的客户端。关掉开关之后，已经出现的「保留外部的版本」仍能写入。替换正式文件之前才出现的未写盘修改同样不写盘。跨清单移动或恢复要换两个文件时，第二个文件替换前才出现的未写盘修改同样返回「待办保存冲突」，两个文件都回到这次写入之前，待办服务不卸下。
