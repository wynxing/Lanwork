# 产品规格

本文规定可见行为。与 [architecture.md](architecture.md) 冲突时，行为以本文为准，机制以架构文档为准。实现状态见 [roadmap.md](roadmap.md)。仓库里还没有这些界面。

平台：所有 Windows 11 x64。背景 API 不可用的版本自动以纯色背景运行。数据目录独立，默认 `%USERPROFILE%\Documents\Lanwork`。不读取、不导入 MayDolist 的数据目录。

沿用是指行为与 MayDolist 1.3.11 的对应模块一致，并写在下面。不是指把 MayDolist 的代码或 WebView 界面搬过来。

## 全局规则

1. 界面文字只允许名称、数量、时间、状态和错误。禁止欢迎语、功能介绍和使用步骤。空列表只显示一行对象名，例如「没有待办」。例外是应用页工具卡片上的一行短说明，由工具作者写在清单里，见「后续规格」。另一条例外是「自定义」里没有工具时：仍显示「没有工具」，并且「导入+」卡片仍在，见「后续规格」。设置页在有新版本时显示该 Release 的发行说明，见「设置」。
2. 不存在「今日」或 Focus 界面、标签、托盘入口和通知落点。
3. 搜索框中的字符只参与搜索。唯一例外是搜索条里以 `/note` 开头的输入，见「快速收集」。除此之外，创建待办或便签必须走待办页、便签页里的明确动作。v0.2.0 之后，外部 AI 可以创建，见「后续规格」。应用页里的工具按 [tools.md](tools.md)，第一批不能新建待办或便签。这些创建都不经过搜索框。
4. 中文输入法组合未上屏时，Enter 不执行搜索结果，也不提交收集。
5. 同时最多一条「当前待办」。它由用户在待办行上指定，写入该条目并在重启后保留。指定另一条则替换。清除后，番茄钟按其规则停止。
6. 写盘失败时保留原文件，并在触发该动作的界面显示错误。
7. 系统关闭透明效果、处于节电模式、透明渲染失败或背景 API 不可用时，亚克力背景改为与主题一致的纯色。不为此显示提示。

## 搜索条

**入口。** 默认热键 `Ctrl+Alt+M`。搜索条已显示时，再按一次收起。

**可见内容。** 无边框圆角窗口，系统亚克力背景。没有记住位置时，出现在光标所在显示器的水平中央，上边缘位于工作区高度 25% 处。记住位置后，出现在上次拖动结束时的位置。只有一个输入框。搜索时，结果列表在输入框下方展开；输入框为空时只显示输入框。收集时显示的内容见「快速收集」。

**动作。** 搜索结果的显示和打开见「搜索」，收集见「快速收集」。可以拖动搜索条来移动它。拖动结束时记住这个位置，下次打开（包括退出进程再启动）出现在那里。拖动不改变输入框里已有的文字选择，也不改变结果的悬停选中和单击打开。拖动过程中不因失焦收起。失焦（拖动过程之外）或输入框为空时按 Esc 收起，不退出进程。搜索时输入框非空，Esc 只清空输入。收起后再打开，输入框为空；未提交的收集文本例外，见「快速收集」。

**禁止。** 标签栏、说明文字、最近使用列表。

**验收。** 再按热键收起。组合输入期间 Enter 不打开结果。从搜索条打开待办或便签结果后，搜索条收起，面板打开并定位到该条。拖动结束后收起再打开，搜索条在松开时的位置；退出进程再启动后仍在该位置。配置里没有记住的位置时，仍出现在光标所在显示器的水平中央，上边缘位于工作区高度 25% 处。在输入框里拖选文字不会移动窗口。悬停一条结果仍选中它，单击仍打开。拖动过程中搜索条不收起；拖动结束后在窗口外点击，搜索条收起。

## 面板

**入口。** 热角默认右上，可设为左上、左下、右下或关闭。多显示器时，每一块显示器上的所选角都可以触发。有全屏应用时不触发热角。按住鼠标左键时不触发，包括拖动窗口经过所选角。光标进入所选热角并连续停留 350ms 后打开面板；这段停留里左键按住过的，从松开后重新计算。光标离开该角后才允许再次触发。停留期间重复打开不发生。托盘右键菜单可打开面板、打开设置、新建便签，以及「退出」。选择「退出」后结束进程；退出前先按「便签」保存未写入的修改。

**可见内容。** 无边框圆角窗口，系统亚克力背景。标题栏为产品名、标签和关闭。标签顺序固定：待办、便签、收纳、应用、设置。默认标签是待办。「应用」页见「后续规格」和 [tools.md](tools.md)，排在 v0.2.0 之后。没有「扩展」标签。标签下方是当前内容。

**动作。** 关闭按钮、失焦和 Esc 收起面板，不退出进程。收起后再打开：标签保持收起前的选择。

**禁止。** 说明段落、玻璃透明度滑块、「今日」标签。

**验收。** 热角关闭后，光标进角不打开面板，搜索条热键仍可用。多显示器时，在任一块显示器的所选角停留后打开面板。有全屏应用时，光标进角不打开面板。按住鼠标左键停在所选角，不打开面板。松开后仍停在角内，再连续停留 350ms 才打开。按住左键把窗口拖过所选角并停留，不打开面板。组合输入期间 Enter 不打开结果。收起不结束进程。托盘「退出」后进程结束。

## 搜索

**入口。** 搜索条获得字符。搜索条里以收集前缀开头的输入不搜索，见「快速收集」。

**可见内容。** 每条显示图标、名称和类型。文件和文件夹结果在名称下方始终用一行小字显示路径。收纳结果在名称下方始终用一行小字显示「收纳 · 分组名」。其它结果选中后才显示路径或所属位置。名称中与输入相同的部分加粗：不区分大小写，只加粗第一处；名称里没有这段原文时不加粗，例如靠拼音、首字母或模糊匹配命中的结果。结果类型为应用、待办、便签、收纳、文件、文件夹、浏览器和网页搜索。分组顺序固定：输入像网址时，最前面是一条浏览器结果，名称为「打开网址」，类型仍是浏览器；其后是应用、待办、便签、收纳、文件和文件夹，网页搜索在最后。这里的「收纳」是收纳分组里的文件、文件夹和网页引用，不是「打开网址」，也不是最后的网页搜索。2026-10-14 决定：这一组取代原来的「网页」组，仍排在便签之后、本机文件之前，因此在应用之后、本机「文件」「文件夹」之前。待办和便签的位置不变。同一条不再以「网页」类型另出现一次。输入不像网址时没有「打开网址」。将要打开的地址是否显示在这一行上，待定。主机名含非 ASCII 字符时是否出现这一条，待定。没有协议、且整个输入只是带一个点的「名称.后缀」时是否出现这一条，待定。

有输入时，结果最后始终有一条网页搜索，名称为「搜索 Google：<输入>」。搜索引擎默认 Google，设置里可改为必应或百度，名称随之为「搜索必应：<输入>」或「搜索百度：<输入>」。这一条不计使用次数。它是否占 20 条上限的名额，待定。

当前可见的前 9 条结果右侧各显示一个按键提示，从上往下依次为 Alt+1 至 Alt+9。结果区滚动后只露出一部分的行是否编号，待定。

组内按命中类型排序：完全匹配、前缀、全拼、首字母、子串、模糊。同一条结果只出现一次，类型取其中最前的一种。使用频率只在同一种命中类型内决定先后，不跨类型比较。每次从搜索结果打开一项，该项的使用次数加 1。同组内、同一种命中类型按使用次数从高到低排列。完全匹配始终排在其他命中类型之前。最多显示 20 条。按分组顺序（浏览器、应用、待办、便签、收纳、文件、文件夹）每组先取至多 8 条；名额还有剩余时，再按这一分组顺序把前面组剩下的结果取完，再取后面的组，直到满 20 条或没有更多结果。

待办只匹配未完成条目的标题，选中后显示所属清单。便签匹配标题、标签和正文，选中后显示所在的一行正文。回收站中的待办和便签不出现。收纳组匹配分组里文件和文件夹引用的名称，以及网页引用的标题和网址。名称和标题与待办标题同一套命中类型。网址只做原文匹配，不做拼音。不匹配路径、分组名和页面正文。类型都是「收纳」。名称下方始终有一行小字，格式与悬浮窗来源行相同：「收纳 · 分组名」，间隔号是 U+00B7，两边各一个空格；分组名没有可见字符时这一行只显示「收纳」。这一行不显示路径或网址，样式与文件结果的路径行相同。同一路径在不同分组里各有一条时，各出现一行。已经显示在「收纳」里的文件，不再出现在本机「文件」组。网页引用在全部收纳里仍只保留一条，不再单独成组。打开后使用次数加 1。文件和文件夹引用：Enter 用 Windows Shell 打开，Ctrl+Enter 打开所在目录；没有壳层图标时用与本机文件、文件夹相同的图形。网页引用：Enter 用默认浏览器打开保存的网址；图标用网站图标缓存，还没有时后台再取，失败或尚未取到时图标位留空，不画地球图标；Ctrl+Enter 仍待定。Everything 未运行或未就绪时，文件和文件夹结果改由 Windows Search 索引提供，只按名称匹配，范围限于 Windows 已建立索引的位置。两者都不可用时，结果区显示「文件索引不可用」，应用、待办、便签和收纳结果保留。

开始菜单里的 `.url` 游戏链接作为应用收录。只收地址以 `steam://run/`、`steam://rungameid/` 或 `com.epicgames.launcher://apps/` 开头的链接。普通网页 `http` / `https` 的 `.url` 不收录。

**动作。** 上下键移动选择。鼠标悬停在一条结果上时选中该条；单击直接打开，等同 Enter。Enter：应用、文件和文件夹结果用 Windows Shell 打开；「打开网址」用默认浏览器打开该网址，没写协议时补成 `https://`，已经写了 `http` 或 `https` 的按所写协议打开；网页搜索结果用默认浏览器打开所选搜索引擎的搜索页，搜索词为输入去掉首尾空白；待办结果打开面板、切到待办并定位该条；便签结果打开面板、切到便签并打开该篇；网页引用结果用默认浏览器打开保存的网址。文件和文件夹结果上 Ctrl+Enter 打开所在目录；应用结果上 Ctrl+Enter 以管理员身份运行；便签结果上 Ctrl+Enter 悬浮该便签。网页引用结果上 Ctrl+Enter 仍待定，见「收纳」。Alt+1 至 Alt+9 直接打开当前可见的第 1 至 9 条结果，等同选中该条后按 Enter；组合输入期间无效，和 Enter 一致。新输入覆盖旧结果，旧查询不得在新输入之后刷回。

便携应用与系统来源是同一启动目标时，搜索结果只显示一条，名称用用户填的名称。别名的目标不在索引里时是否单独成条，待定。

应用结果上 Ctrl+Enter 以管理员身份运行，交给 Windows Shell，动词 `runas`，由系统显示 UAC 提示。Ctrl+Shift+Enter 同样以管理员身份运行。没有本地可执行文件时这两个快捷键无效。用户取消 UAC 提示时不显示错误，也不记使用次数。

在应用结果上右键打开菜单，样式与搜索条一致：同一套字体、圆角和选中底色，提示在右侧。菜单项顺序是「以其他用户身份运行」（Alt+1）、「以管理员身份运行」（Alt+2）、「打开文件所在文件夹」（Alt+3）、「打开目标文件夹」（Alt+4）、「隐藏」（Alt+5）。菜单打开时，Alt+数字选择菜单项，不再打开搜索结果；没有对应项的数字没有动作。鼠标悬停高亮一项，单击执行。Esc 关闭菜单，在菜单外点击也关闭，这次点击不打开底下的结果。

「以其他用户身份运行」交给 Windows Shell，动词 `runasuser`，由系统显示凭据对话框。用户取消该对话框时与取消 UAC 相同。「打开文件所在文件夹」打开这一条索引文件所在的目录，文件可以是快捷方式、游戏链接或可执行文件本身。「打开目标文件夹」打开快捷方式目标所在的目录；没有目标时这一项仍在菜单里，但是不可用，Alt+4 没有动作。没有本地可执行文件时，「以其他用户身份运行」和「以管理员身份运行」不可用。没有索引文件时，「打开文件所在文件夹」不可用。

「隐藏」之后该应用不再出现在搜索结果，并写入 `user-apps.json`。设置页「隐藏的应用」列出这些应用，每条有「恢复」。写盘失败时隐藏或恢复不生效，并显示错误。

**禁止。** 把非 `/note` 开头的搜索词存成便签。把搜索词存成待办或收纳里的网页引用。在结果上编辑待办或便签。搜索文件内容。复制或移动命中的文件。

**验收。** 连续输入时，中间结果不覆盖最后一次输入。Everything 不可用时，已建立索引位置中的文件仍能按名称搜到；Windows Search 也不可用时，仍能打开应用、待办、便签和收纳。Windows Search 回退时，只有正文命中的文件不出现。输入不像网址时没有「打开网址」。已完成的待办和回收站中的条目不出现。从搜索结果打开待办会打开面板并定位该条（安装版与点击到期通知落到同一位置；便携版通知不定位，但搜索打开仍定位）。从结果打开一项后，该项使用次数增加；同组同类中次数更高的排在前面。完全匹配仍排在其他命中类型之前。开始菜单中的 Steam、Epic 游戏链接能作为应用搜到；普通网页 `.url` 不出现在应用结果里。隐藏后的应用不在搜索结果中，设置页「隐藏的应用」里点「恢复」后可以再次搜到。在有本地文件的应用结果上 Ctrl+Enter 会提起 UAC；取消 UAC 后不显示错误。右键菜单按上述五项出现；没有快捷方式目标时「打开目标文件夹」不可用。菜单打开时 Alt+1 执行「以其他用户身份运行」，不再打开第一条搜索结果。有输入时最后一条是「搜索 Google：<输入>」，打开后默认浏览器显示 Google 的搜索页，该条使用次数不增加；设置改为必应或百度后，这一条随之改变。输入像网址时，第一条名称是「打开网址」。`cursor.com` 按 Enter 或单击后，默认浏览器打开 `https://cursor.com`；`https://cursor.com/dashboard` 按所写地址打开；`http://cursor.com` 仍按 `http` 打开。网页搜索仍在最后，网页搜索的使用次数不增加。「打开网址」打开后使用次数加 1。Alt+1 打开「打开网址」。Alt+2 打开当前可见的第二条；组合输入期间按 Alt+数字不打开结果。悬停选中和单击等同 Enter，与其它结果相同。收纳里的文件、文件夹和网页引用出现在「收纳」组：排在便签之后、本机文件之前；第二行是「收纳 · 分组名」；已经显示的文件不在「文件」组再出现一次；网页引用不再以「网页」类型另出现。文件 Enter 打开、Ctrl+Enter 打开所在目录。网页引用按标题和网址都能搜到：标题与待办标题同一套命中类型，网址只做原文、不做拼音。标题上的命中不会排在只命中网址的更弱命中之后。同一条只出现一次。名称里与输入相同的部分加粗；只命中网址、标题里没有这段原文时，标题不加粗。文件和文件夹仍只按名称匹配，不按路径。网页引用 Enter 用默认浏览器打开，图标来自网站图标缓存，没有时该位留空。打开后使用次数加 1。这一组排在 v0.4.0。

索引来源、拼音、条数和图标缓存见架构文档。

## 快速收集

**入口。** 搜索条输入框的内容以收集前缀 `/note` 开头。没有独立窗口和独立热键。

收集前缀必须位于输入开头：

- `/note`：收集便签。后面必须是空白或结束；`/notes` 这类紧挨着的词按搜索处理。

**可见内容。** 收集时不显示搜索结果，输入框下方只有一行预览和一行错误。便签预览显示「便签」和标题，没有标题时显示「无标题」。

**动作。** `/note` 创建便签，并打开该便签的悬浮窗进行编辑；`/note` 后的文字作为便签标题。创建成功但悬浮窗没有打开时，只重新尝试打开悬浮窗，不重新创建便签。仍失败则提示「便签已保存，悬浮失败」，该便签留在列表里。

Enter 提交，然后清空输入框并收起搜索条。按 Esc、失焦或再按热键收起时，保留未提交的收集文本，下次打开搜索条时原样恢复。提交失败时保留文本并显示错误。收集前缀之后只有空白时，Enter 不创建记录。

**禁止。** 收集时向文件索引发查询。

**验收。** 不以 `/note` 开头的输入按 Enter 不创建任何记录。组合输入期间 Enter 不提交。收集文本收起后再打开仍在。删掉前缀后，输入框立即回到搜索。便签已创建但悬浮失败时，重试不产生第二篇；仍失败时显示「便签已保存，悬浮失败」，列表里有这一篇。

## 待办

**入口。** 待办标签。待办悬浮窗也从待办标签打开，见「悬浮窗」。安装版的到期通知被点击时，打开面板、切到待办并定位该条。便携版的到期通知只显示提醒，点击不定位。收纳分组悬浮窗的「关联待办」里点一条的标题，也是打开面板、切到待办并定位该条。

**可见内容。** 清单列表。系统收件箱清单存在且不重复创建。条目显示标题；有到期日、周期、来源或关联收纳分组时显示对应标记。一条待办被一个或多个收纳分组关联时，都只是同一个收纳标记；标记是否显示分组数量待定。逾期数量可出现在托盘徽标上，数量为 0 时不显示徽标。

**动作。**

| 动作 | 结果 |
| --- | --- |
| 新建、改标题、排序 | 写入对应清单 |
| 完成 | 条目标为完成；带周期规则时生成下一次，直到重复截止日。没有重复截止日时照常生成下一次。在重复截止日当天完成，不再生成下一次。每月重复的 31 日，在没有 31 日的月份落到该月最后一天；下一次仍按原来的日子（1 月 31 日、2 月 28 日或 29 日、3 月 31 日）。原来的日子记在周期上。旧记录没有该字段时，用当前到期日的日子。29 日或 30 日在目标月不存在时落到哪一天仍待定 |
| 取消完成 | 已完成的条目标回未完成，排回原来的位置。重复待办在完成时已经生成的下一次一并删除。下一次已被用户改过或已经完成时是否删除仍待定 |
| 软删除 | 进入回收站。恢复后回到原清单；原清单已删除时，回到默认清单 |
| 永久删除 | 只在回收站中。进入回收站满 30 天后自动清除 |
| 到期日、提醒、周期 | 字段为每天、每周、每两周、每月。提醒到点发系统通知。睡眠或关机期间错过的多条提醒，恢复后合并成一条补发，可以展开查看各条。安静时段内不弹出；时段结束后，错过的多条提醒同样合并成一条补发，可以展开查看 |
| 打开来源 | 仅 `http` / `https`；其他协议拒绝 |
| 设为当前 / 清除当前 | 遵守全局规则 5 |
| 打开关联收纳 | 仅当有收纳分组关联该条时可用；切到收纳并选中该分组，关联多个分组时选中第一个。收纳分组可以关联多条待办，这里只看这一条被哪些分组关联 |
| 处理模式 | 只作用于收件箱未完成条目，一次一条 |

处理模式的按键：

| 键 | 结果 |
| --- | --- |
| `1` | 到期日设为今天 |
| `2` | 到期日顺延，天数由设置指定，默认 3，允许 1 至 30 |
| `3` | 选目标清单后移动，保留来源 |
| `4` | 完成 |
| `5` | 软删除 |
| Esc | 退出处理模式，回到清单 |

处理模式不另存一套数据。光标按条目 id 前进。写盘失败时停在当前条并显示错误。组合输入不触发 `1` 至 `5`。按住 Esc 退出处理模式时，同一次按住的重复不收起面板；松开后再按 Esc 才收起。

**界面。** 2026-10-14 决定。收件箱有未完成条目时，该清单顶部有「处理 N 条」，N 是这些条目的数量。点它进入处理模式。待办页换成一张居中的卡片，上面是标题、到期日和来源；卡片上方一行小字，例如「第 3 / 12 条」。卡片下方五个小按钮：「1 今天」「2 稍后 3 天」「3 移动」「4 完成」「5 删除」。天数用设置里的「稍后」天数，点击和对应的键相同。颜色跟随主题，用淡色，不用醒目的强调色。按 `3` 或点「3 移动」时，清单选择盖在卡片上，上下键移动，Enter 确认，Esc 只关掉选择。最后一条处理完显示「收件箱已清空」，1 秒后回到清单。

**悬浮窗。** 2026-10-13 决定。全程序只有一个待办悬浮窗。它列出全部清单里未进回收站的待办，含已完成。收纳分组悬浮窗里的「关联待办」仍只列出该分组关联的那几条，见「收纳」。番茄钟仍是另一个窗口，见「番茄钟」。到期通知仍按上面的入口打开面板并定位。入口是待办页上的「悬浮」按钮，和便签页的「悬浮」一样。当前停在回收站时这个按钮仍在，因为窗口不跟当前清单走。已经打开时，再次打开只把焦点给这个窗口。每条至少有勾选和标题。逾期的待办整行文字变成红色。什么算逾期，与托盘上的逾期数量相同：未完成、不在回收站、到期日早于今天。到期日就是今天时不算逾期。读不到今天的日期时不标红。没有要列出的待办时，只显示「没有待办」。拖动条下面一行来源，见「便签」的「来源行」：这一行就是「待办」。失焦后的磨砂见「便签」的「背景」。

窗口里的动作：

| 动作 | 结果 |
| --- | --- |
| 勾选完成 | 未完成的条目勾选后，走待办现有的完成：标为完成；带周期规则时按「完成」生成下一次。写盘失败时该条不变，并在这个窗口显示错误。待办页上同一条随之变为完成 |
| 取消完成 | 已完成的条目取消勾选后，走待办页现有的「取消完成」：标回未完成，排回原来的位置。重复待办在完成时已经生成的下一次，若还是当时生成的那一条，一并删除。下一次已被用户改过或已经完成时是否删除仍待定。写盘失败时该条不变，并在这个窗口显示错误。待办页上同一条随之变回未完成 |
| 新建 | 不能。窗口里没有新建框 |
| 修改 | 不能改标题、到期日、提醒、周期、来源或所属清单 |
| 关闭 | 只关闭窗口，不删除待办 |
| 最上层与贴边 | 与便签悬浮窗相同，见「便签」。始终在其他窗口之上，没有钉住按钮。贴边、把手、点把手展开、再点或失焦收回、拖离后取消贴边，都同一套。这个窗口记住贴住的边、沿边位置和是否收起 |
| 叠页 | 与便签悬浮窗相同，见「便签」。可以和便签悬浮窗、收纳悬浮窗落在同一叠。展开并且至少两页时，彩色圆点在窗口下方靠左、与窗口左边缘对齐、紧贴窗口下沿、内容区外面 |
| 左右方向键 | 处于叠页且至少两页时翻页，与收纳悬浮窗相同 |
| 位置与大小 | 记住位置和大小。关闭后再打开、重启后再打开，用记下的值。不贴边时整扇留在所在显示器的工作区里，规则见「便签」的「工作区」。贴边时仍按贴边，不拉回工作区 |
| 面板收起 | 面板收起或失焦时，这个窗口不关闭 |
| 记住 | 位置、大小、贴边和叠页都会记下，导出、备份、导入之后仍在。不在叠里时，重启后不会自己打开，再次打开仍用记下的位置和大小。已经叠在一起时，按「便签」的叠页在启动时打开 |

待办悬浮窗默认大小 320×360，最小尺寸 200×120。无独立托盘项或热键，仅从待办页的「悬浮」按钮打开。条目仅展示勾选框与标题，不展示清单名、分段隔断或额外标记；逾期条目整行文字标红（浅色模式 `#c42b1c`，深色模式 `#ff99a4`）。回收站条目不列出；条目按清单顺序平铺列出，无分段隔断，各清单内未完成在前、已完成在后，各自保持条目在清单中的原有先后顺序。勾选完成与取消完成即时生效并同步待办页，窗口内不支持新建、编辑或删除。左右方向键在多页叠放时用于翻页。

**禁止。** 在待办页展示其他模块的聚合列表。在待办悬浮窗里新建待办或修改已有待办。把待办悬浮窗做成「今日」或 Focus。把到期通知打开到待办悬浮窗。关闭待办悬浮窗时删除待办。

**验收。** 收件箱有未完成条目时，清单顶部有「处理 N 条」。进入后一次一条，卡片上是标题、到期日和来源，上方是「第 3 / 12 条」这样的进度。`1` 把到期日设为今天，`2` 按设置的天数顺延（默认 3），`3` 弹出清单选择，上下键选择，Enter 移动并保留来源，Esc 只关掉选择，`4` 完成，`5` 软删除。五个按钮和按键相同。组合输入期间 `1` 至 `5` 不触发。写盘失败时停在当前条并显示错误。光标按条目 id 前进。最后一条之后显示「收件箱已清空」，1 秒后回到清单。Esc 退出处理模式。按住 Esc 退出时，同一次按住的重复不收起面板；松开后再按 Esc 才收起。

重启后到期日、周期、来源和当前标记仍在。旧记录缺少这些字段时仍能打开。安装版的通知点击落到待办中的该条，不打开一个名为今日的页面。便携版的通知点击不定位。每月重复的 31 日，在没有 31 日的月份落到该月最后一天，下一次仍回到原来的日子。没有重复截止日时，完成后仍生成下一次。在重复截止日当天完成后没有下一次。取消完成后，该条回到未完成，位置与完成前相同。重复待办完成时生成的下一次，若还是当时生成的那一条，则不再存在。清单里不能永久删除。回收站中超过 30 天的待办被清除。原清单已删除时，恢复回到默认清单。睡眠或关机后错过的多条提醒合成一条，展开后能看到各条。安静时段内不弹出提醒，结束后同样合成一条。

待办悬浮窗的范围是全部清单里未进回收站的待办，已完成的也列出。收纳分组悬浮窗仍只列出该分组关联的待办。从待办页的「悬浮」打开；已经打开时只把焦点给这一个，不出现第二个窗口。回收站视图里这个按钮仍在。勾选一条未完成的待办后，该条标为完成；带周期的生成下一次，与在待办页完成相同，待办页上同一条也是完成的。取消勾选一条已完成的待办后，该条标回未完成；重复待办完成时生成的下一次，若还是当时生成的那一条，则不再存在，与在待办页取消完成相同。下一次已被用户改过或已经完成时是否删除，仍待定。待办页上同一条也变回未完成。写盘失败时该条不变，窗口上有错误。窗口里不能新建，也不能改标题、到期日、提醒、周期、来源或所属清单。逾期的判定与托盘逾期数量相同，这些条目整行文字变成红色。到期日是今天、已完成、在回收站，或读不到今天的日期时，不标红。没有要列出的待办时只显示「没有待办」。窗口上没有钉住按钮，始终在其他普通窗口之上。记住位置和大小；不贴边时整扇留在所在显示器的工作区里，规则见「便签」的「工作区」。贴边和叠页与便签悬浮窗相同，并且可以和便签悬浮窗、收纳悬浮窗落在同一叠，彩色圆点在窗口下方靠左、与窗口左边缘对齐、紧贴窗口下沿、内容区外面。勾选框不获取键盘焦点；窗口处于叠页且至少两页时，左右方向键翻页。关闭窗口不删除待办。面板收起后窗口仍在。不在叠里时，重启后不会自己打开，再次打开仍用记下的位置和大小。已经叠在一起时，重启后按「便签」的叠页打开。导出再导入之后，位置、贴边和叠页仍在。没有这份记录的旧数据仍能打开待办。安装版到期通知的点击仍然打开面板并定位该条。展开时拖动条下面一行是「待办」，没有某一条的标题，收成把手时这一行不在。透明效果可用时失去焦点后仍是同一种半透明磨砂；纯色回退与全局规则 7 相同。这项验收还没有在 Windows 上执行。

## 便签

**入口。** 便签标签，或托盘「新建便签」。

**可见内容。** 便签列表和正文。可显示置顶和标签。列表里的「置顶」只决定便签在列表里的先后。悬浮窗没有单独的置顶开关。

**动作。** 新建、编辑、打标签、按标签筛选、置顶、删除。按文字查找使用全局搜索。停止编辑 1 秒后自动保存。删除后进入回收站，保留 30 天，可以恢复或永久删除。悬浮：打开含该便签正文的独立窗口，拖动条下面一行显示来源，见「来源行」；每篇便签记住自己的悬浮窗位置和大小，再次打开时使用。同一篇已经有悬浮窗时，再次悬浮只聚焦该窗口。关闭悬浮窗后正文仍留在便签列表。多个悬浮窗可以同时存在。同一篇在面板和悬浮窗里同时修改时，后保存的一方弹出提示，由用户选择保留哪个版本。关闭便签窗口或退出程序时，先自动保存未写入的修改。保存失败时提示，可以选择重试，或放弃修改后继续关闭或退出。

**多选。** 2026-10-14 决定。只在面板的便签列表。回收站和悬浮窗没有多选。列表顶部有「选择」。点它进入多选：每一行出现勾选框，列表底部出现操作条，写「已选 N 条」。这个按钮这时显示「完成」，点它退出多选。Esc 也退出。退出后勾选框和操作条消失，勾选不保留。退出多选不收起面板。

不在多选时，Ctrl+点击一行，把这一行勾上并进入多选，不打开编辑。Shift+点击从当前打开的那一篇连到点的这一行，这一段成为勾选，并进入多选，不打开编辑。当前没有打开的便签，或打开的那一篇不在当前列表里时，Shift+点击只勾上点的这一行。已经在多选时，点击一行只切换这一行的勾选，不换编辑区里的便签。Ctrl+点击同样只切换这一行。Shift+点击从锚点连到这一行，这一段成为勾选，段外的勾选去掉。锚点是上一次普通点击或 Ctrl+点击的那一行；还没有时用当前打开的那一篇。同时按着 Ctrl 和 Shift 时，按 Shift 这一段处理。在一行上按下，只有松开时仍在这一行里才算点击。在另一行或列表外松开，普通列表不打开这篇，多选不改勾选，回收站也不选中这一条。

操作条上有「全选」「取消全选」「浮出」「删除」。「全选」勾上当前列表里的每一行。有标签筛选时，当前列表只是筛出来的这些。「取消全选」去掉全部勾选，仍留在多选。「浮出」按列表顺序把已勾选的每一篇打开成悬浮窗。已经有悬浮窗的只聚焦，位置和大小用各自记住的值。「删除」先换成「确认删除」和「取消」。点「取消」只撤回这次确认，勾选还在，便签不变。点「确认删除」后，已勾选的都软删除，进入回收站，可以恢复。写盘失败的仍留在列表里，并显示错误。没有勾选时「浮出」和「删除」不可用。点「选择」时若已经打开一篇，这篇就是 Shift 的锚点，但不会因此被勾上。

**最上层。** 便签悬浮窗始终在其他窗口之上。没有按这一篇单独开关的置顶。旧数据里如果还有以前的钉住字段，打开时忽略，窗口仍然在最上层，这个字段不再写回去。最上层不改变便签的置顶，不改变正文，也不使便签出现冲突提示。

**贴边。** 拖动悬浮窗，松手时窗口碰到某块屏幕外侧的左边、右边或上边，就收成贴在这条边上的一个小把手。拖出屏幕再松开时，先把窗口收进所在显示器的工作区；收进去之后，只按松开时越出工作区的那一侧再判断。这一侧是可贴的外沿（左、右或上）才同样收成把手。底边越出时，夹回后上边即使碰到屏幕上沿也不收。窗口在越出的方向上铺满工作区时，贴越出的那一侧，不改贴对侧。只改大小、按记住的位置再打开，或内容把窗口撑大，只收进工作区，不因此贴边。把手厚 3 逻辑像素、长 40 逻辑像素，两端圆角，半透明灰色；亮色主题用深灰，暗色主题用浅灰，都随屏幕缩放。没有单独的图标。鼠标停在把手上，把手变得更亮、更不透明。能点、能悬停的范围就是这块把手，没有更大的透明点击区。把手沿这条边，放在窗口贴住位置的正中。收起之后，窗口就是这个把手，没有横跨整条边的色条，一键回到桌面之后也一样。展开后，同一条边的正中仍有这个把手。两块屏幕共用的那条边不算外侧，松手在那里不收起。底边不贴。点把手，窗口展开；再点把手，或窗口失去焦点，就收回成把手。把展开的窗口拖离这条边再松开，就取消贴边，之后失焦不再自动收起。贴住的是哪条边、沿边的位置、以及当前是展开还是收起，关闭后再悬浮、以及重启后再悬浮，都还是上次的。收起的把手也在最上层，全屏程序在前面时把手仍然看得见。收纳悬浮窗和待办悬浮窗同样如此，见「收纳」「待办」。

**工作区。** 不贴边的便签悬浮窗、收纳悬浮窗和待办悬浮窗，拖动过程中不限制离开工作区；在拖动松手、按记住的位置再打开、改变大小，或内容把窗口撑大之后，整扇都留在它所在显示器的工作区里。工作区躲开任务栏。所在显示器按整块屏幕（含任务栏）的重叠面积来定，不按工作区；都不重叠时，用光标所在的那一块。然后把窗口收进这一块的工作区，缩放用这一块的。只落在任务栏那一条里、和工作区不相交时，仍算这一块，不改去光标所在的屏幕。大小和位置都是那块屏缩放后的物理像素。便签、收纳和待办悬浮窗至少 200×120 逻辑像素，按那块屏的缩放换成物理像素；先把大小收到工作区里，再移动位置。工作区比这个最小尺寸还小时，缩到和工作区一样大，界面上的最小尺寸也一起放开。已经记下的宽高仍是物理像素，不按缩放重算。叠在一起时，各页共用这一份位置和大小，同样留在工作区里。拖动松手时，窗口先按「贴边」判断；没贴上的再收进工作区，收进去之后只按越出的那一侧再判断一次，这一侧是可贴的外沿才收成把手。只改大小、再打开和内容撑大不再判断一次。贴边对得上时按「贴边」，不把展开的窗口或把手拉回工作区。展开并且至少两页时，页点那一行也留在同一块工作区里。

贴边里这些还没有定：离屏幕边多近算碰到；窗口同时碰到两条边时贴哪一条；展开和收回要不要滑动、滑多久；收起之后拖着把手再松开怎么算；收起的把手上能不能直接关闭；贴着边时改变窗口大小怎么算；屏幕布局变了、记下的那条边不再是外侧时，下次打开放在哪里、要不要忘掉贴边；贴的是显示器外沿，还是躲开任务栏的工作区；独占全屏会不会盖住最上层的把手；窗口已经收起时，再次悬浮是只聚焦，还是顺便展开。

**叠页。** 把一个悬浮窗拖到另一个上，松手时重叠超过一半，就合成一叠。便签悬浮窗、收纳悬浮窗和待办悬浮窗可以在同一叠里。一叠同一时刻只显示一页，各页共用这一份位置和大小。叠着的窗口有焦点时，左方向键、右方向键翻页；正文输入框有焦点时，这两个键留给文字，不翻页。展开并且至少两页时，窗口下方靠左、与窗口左边缘对齐、紧贴窗口下沿、内容区外面，有一排彩色圆点，一页一个。圆点直径 16 逻辑像素，相邻间隔 4 逻辑像素，这一行高 16 逻辑像素，随所在屏幕缩放。颜色按页序循环八种：红 #FF5F57、黄 #FEBC2E、绿 #28C840、蓝 #5AC8FA、紫 #BF5AF2、橙 #FF9F0A、粉 #FF6B9D、青 #2EB8C8，第九页回到红。当前页不透明，并有 1.5 逻辑像素的白色细光圈。其余页用同一种颜色，透明度 0.42。鼠标停在圆点上时，该点透明度提到 0.72；已经是当前页的仍不透明，光圈改为纯白。点一个圆点就换到那一页。把某一个圆点拖出去，就把那一页拆成独立的悬浮窗。拖标题栏只移动整叠，不拆页。整叠一起贴边。收起的把手上用小点表示这一叠有几页。两条已经收起的悬浮窗贴在同一条屏幕边上、彼此靠近时，自动合成一叠。一叠有哪些页、当前是哪一页、贴边状态，重启后再悬浮仍在。重启后，已经叠在一起的悬浮窗会再打开，只显示上次那一页，仍是一个窗口；收起时仍是一个把手，小点在把手上，展开时彩色圆点在窗口下方靠左。页不会少。没有叠起来的悬浮窗不会因此打开。没有叠页记录的旧文件照常打开。

叠页里这些还没有定：超过一半按哪一个窗口的面积算，刚好一半算不算；合成后用哪一份位置和大小、页怎么排、当时显示哪一页；翻到头要不要回到另一头；页点最多画几个；下方放不下时要不要改到窗口上方；把手上的点最多几个、怎么排；两条收起的把手多近算靠近；关掉叠着的窗口后这一叠还在不在、再次悬浮打开哪一页；同时盖住多个窗口时并进哪一个；叠的编号怎么生成。

**来源行。** 2026-10-14 决定。展开的便签悬浮窗、收纳悬浮窗和待办悬浮窗，在拖动条下面单独一行显示这一页的来源。格式是「类型 · 名称」，中间的间隔号是 U+00B7，两边各有一个空格。这一行比正文小、颜色更淡，按下它不拖动窗口。一行放不下时末尾省略号，不换行。收成把手时不显示这一行。单独打开的便签、收纳、待办都有这一行。叠在一起时，当前看得见的那一页显示自己的来源：这一页是便签、收纳或待办，就按那一种取名；翻到另一页后换成那一页的来源。页点圆点在内容区外面，不显示来源行。拖动、关闭、最上层、贴边收起和页点圆点都保持原来的位置和行为。

便签这一行是「便签 · 名称」。名称按顺序取：标题里第一个去掉首尾空白后还有字的行；没有这样的标题行时，用正文里第一个这样的行；标题和正文都没有时用「无标题」。在悬浮窗里改正文，这一行跟着当前草稿变。面板里改了标题或正文，只有这篇悬浮窗没有未保存的修改时，才换成保存后的内容。这一行是名称，不是说明文字。

收纳这一行是「收纳 · 分组名」。分组名取名称里第一个去掉首尾空白后还有字的行。分组改名后，已经打开的这扇窗口马上换成新名字。分组已经不在，或名称没有可见字符时，这一行只显示「收纳」。默认分组名叫「收纳」时，这一行是「收纳 · 收纳」。来源行的下一行仍是可折叠的「关联待办」，再下面是条目。

待办这一行就是「待办」，没有间隔号，也不带某一条待办的标题。这个窗口列出全部清单，没有单独的名称。

**背景。** 2026-10-14 决定。透明效果可用时，便签悬浮窗、收纳悬浮窗和待办悬浮窗在有焦点和失去焦点时是同一种半透明磨砂，失焦后仍是这一层。叠在一起时，看得见的那一页无论是这三种里的哪一种，失焦后仍是这一层；翻到另一页后，那一页同样如此。透明效果关闭、节电模式，或系统提供不了这种背景时，仍用与主题一致的纯色，规则见全局规则 7，失焦也不换成另一种颜色。收起的把手仍是原来的半透明灰色，不用这层磨砂。页点圆点保持透明，失焦不铺上不透明的底。

**禁止。** 悬浮窗里的说明文字。来源行是这一页的名称，见「来源行」。关闭悬浮窗时删除便签。悬浮时改变便签的置顶。悬浮窗里多选。在多选里批量置顶、批量打标签，或把便签移到收纳。

**验收。** 停止编辑满 1 秒后写入。自动保存失败时正文还在窗口里，并显示错误。关闭窗口或退出时若保存失败，可以重试或放弃修改。关闭后再开，正文与关闭前最后一次成功保存一致。同一篇已有悬浮窗时再次悬浮，焦点回到该窗口，位置和大小仍是记住的值。删除后列表里不再显示，回收站里可以恢复；超过 30 天被清除。后保存的一方不直接覆盖，先出现选择版本的提示。悬浮窗上没有钉住按钮，窗口始终在其他普通窗口之上。把窗口拖到屏幕外侧的左边、右边或上边松开，收成把手；拖出这三条边再松开，先回到工作区边缘，然后收成把手；窗口几乎铺满工作区时，底边越出不贴上边，右边越出不改贴左边；拖到两块屏幕共用的边上松开，不收成把手；底边不收，拖出底边只回到工作区。只改大小时越出工作区，回到工作区里，不收成把手。不贴边时，拖出工作区后松手、按记住的位置再打开、改大小，或内容把窗口撑大，整扇都留在所在显示器的工作区里；叠在一起时共用这一份位置和大小，同样留在工作区里。贴边时仍按贴边，不拉回工作区。展开并且至少两页时，页点那一行也留在这块工作区里。点把手展开，再点把手或让窗口失去焦点就收回。把展开的窗口拖离这条边松开后，失焦不再收回。关闭后再悬浮、重启后再悬浮，贴边和收起状态仍在。带有旧钉住字段的便签仍能打开，置顶、正文和列表顺序不变。导出再导入、备份再恢复之后，贴边仍在。全屏程序在前面时把手仍能看见。收起之后看得见的只有这个把手，没有横跨整条边的色条，一键回到桌面之后也一样。把一个悬浮窗拖到另一个上，重叠超过一半后松开，合成一叠，只看到一页，位置和大小是同一份；便签、收纳和待办可以在同一叠。叠着的窗口有焦点、正文没有焦点时，左右方向键换页；正文有焦点时左右键留在文字里。彩色圆点在窗口原有边框外面、下方靠左并与窗口左边缘对齐、紧贴窗口下沿，不占内容区；按页序循环红、黄、绿、蓝、紫及同系色，当前页不透明并有细光圈，其余页更透，悬停时稍亮。点一个圆点换到那一页。把某一个圆点拖出去，那一页成为独立悬浮窗。拖标题栏只移动整叠，不拆页。整叠贴边后收成一个把手，把手上的点数出页数。两条收起的把手在同一条屏幕边上靠近时合成一叠。重启后再悬浮，成员、当前页和贴边仍在。重启后，贴在上边并且收起的一叠再出现时仍是一个把手，页点在把手上，成员都还在这一叠里。没有叠页记录的旧便签仍能打开。展开的悬浮窗在拖动条下面有一行来源：标题有可见行时是「便签 · 」加那一行，否则是「便签 · 」加正文里第一个有字的行，都没有时是「便签 · 无标题」。在悬浮窗里改正文，这一行跟着变。一行放不下时末尾省略号。收成把手时这一行不在。叠在一起时，看得见的那一页显示自己的来源。拖动条、关闭、贴边和页点仍在原来的位置。透明效果可用时，窗口失去焦点后仍是同一种半透明磨砂；透明效果关闭、节电或背景不可用时仍是与主题一致的纯色。收起的把手仍是半透明灰色。来源行和失焦后的磨砂还没有在 Windows 上对照屏幕验收。点「选择」后出现勾选框和操作条，「已选 N 条」随勾选变化。点「完成」或按 Esc 后勾选框和操作条消失，面板不收起。Ctrl+点击、Shift+点击不进入编辑。批量删除先确认，确认后这些便签进入回收站并且可以恢复；取消则列表不变。批量浮出后每篇一个悬浮窗，位置用各自记住的值，已经打开的不重复。写盘失败时显示错误，没删掉的仍在列表里。回收站和悬浮窗上没有「选择」，也没有勾选框。在一行上按下后在另一行或列表外松开，不打开、不改勾选、不选中回收站里的那一条。这项多选还没有在 Windows 上对照屏幕验收。

## 收纳

**入口。** 收纳标签，或待办上的「打开关联收纳」。收纳分组的悬浮窗从收纳标签里打开，入口按钮的位置待定。

**可见内容。** 分组列表，每组显示名称和条目数；关联了待办的分组同时显示所关联各条待办的标题；多条标题在分组列表和分组详情里具体怎么排版待定。选中分组后列出条目。文件和文件夹条目显示图标和名称，选中后显示完整路径。路径不存在的条目显示「路径不存在」。网页条目保存网址、标题和网站图标，选中后显示网址。网站图标与文件条目共用图标位。还没有取到，或获取失败时，该位留空，不画通用的地球图标，也不因此显示「路径不存在」。标题缺失时怎么显示，见「网页引用」的待定。没有分组时只显示「没有分组」。

**动作。**

| 动作 | 结果 |
| --- | --- |
| 新建、重命名、排序分组 | 写入该分组 |
| 删除分组 | 确认后删除分组和其中的引用，不动原文件，也不关闭、不移动浏览器标签 |
| 拖入文件或文件夹 | 加入当前选中的分组；没有分组时先创建名为「收纳」的分组。可一次拖入多个。只保存路径引用，不移动、不复制原文件 |
| 拖入网址 | 见「网页引用」。加入的分组与拖入文件相同。只保存引用，不关闭、不移动浏览器标签 |
| 重复拖入同一路径 | 同一分组内同一路径不新增；不同分组可以各有一条。网址不沿用本行，见「网页引用」：全部收纳里同一网址只保留一条 |
| 文件或文件夹条目上单击 | 选中这一条，不打开。多条时见「条目多选」 |
| 文件或文件夹条目上 Enter 或双击 | 用 Windows Shell 打开当前选中的条目 |
| 文件或文件夹条目上 Ctrl+Enter | 打开所在目录。选中多条时，对其中每条路径引用打开所在目录 |
| 点击网页条目 | 单击选中，不打开。Enter 或双击用默认浏览器重新打开保存的网址。Ctrl+Enter 仍待定，见「网页引用」 |
| 把选中的条目拖到另一个分组 | 见「条目多选」。引用改到那个分组，不移动、不复制原文件，也不关闭、不移动浏览器标签 |
| 拖出文件或文件夹 | 按原路径提供文件，只允许复制和创建快捷方式，不允许移动。指针还在面板里时见「条目多选」，离开窗口才拖出。网页条目能否拖出，见「网页引用」的待定 |
| 移除引用 | 从分组删掉该条。文件或文件夹不删除原文件。网页引用不关闭、不移动浏览器标签 |
| 关联待办 / 解除关联 | 关联时弹出搜索框，输入关键字筛选待办，点击一条即关联。一个分组可以关联多条待办，同一条待办在同一分组里只关联一次；一条待办也可以被多个分组关联。解除关联针对其中一条，不影响该分组的其余关联 |
| 悬浮 | 把该分组打开成独立窗口，只显示该分组的条目。拖动条下面一行来源，见「便签」的「来源行」：分组名是「收纳 · 名称」，改名后这扇窗口马上更新；分组已经不在或名称没有可见字符时，这一行是「收纳」。来源行下面仍是「关联待办」，再下面是条目。失焦后的磨砂见「便签」的「背景」。面板收起或失焦时悬浮窗不关闭。每个分组记住自己悬浮窗的位置和大小，再次打开时使用。同一分组已有悬浮窗时再次悬浮，只把焦点切到该窗口。可以同时有多个分组的悬浮窗 |
| 关闭悬浮窗 | 只关闭窗口，不删除分组和其中的引用 |
| 最上层与贴边 | 悬浮窗始终在其他窗口之上，没有单独的钉住按钮。贴边规则与便签悬浮窗相同：松手碰到屏幕外侧的左、右或上边就收成把手；拖出屏幕后先收回工作区边缘，贴住外侧再收成把手。共用边和底边不收；点把手展开，再点或失焦收回；拖离这条边就取消贴边。不贴边时整扇留在所在显示器的工作区里，规则见「便签」的「工作区」。每个分组记住贴住的边、沿边位置和是否收起。旧数据里的钉住字段忽略，不再写回。不改变分组、条目和关联待办 |
| 叠页 | 与便签悬浮窗相同，见「便签」。收纳悬浮窗可以和便签悬浮窗、待办悬浮窗叠在一起 |
| 往悬浮窗拖入文件或文件夹 | 加入该悬浮窗对应的分组，规则与往面板拖入相同：只保存路径引用，重复拖入不新增 |
| 往悬浮窗拖入网址 | 加入该悬浮窗对应的分组，规则与往面板拖入网址相同 |
| 从悬浮窗拖出 | 与从面板拖出相同：按原路径提供文件，只允许复制和创建快捷方式，不允许移动；Esc 取消。网页条目能否拖出，见「网页引用」的待定 |
| 在悬浮窗里移除引用 | 与在面板里相同：选中一条后用「移除引用」按钮，只从该分组删掉这一条。文件或文件夹不删除原文件。网页引用不关闭、不移动浏览器标签 |
| 悬浮窗里的「关联待办」 | 悬浮窗里有一个可以折叠的「关联待办」区域，默认收起；展开后列出该分组各关联待办的标题 |

| 在悬浮窗里打开网页条目 | 单击选中，不打开。Enter 或双击用默认浏览器重新打开保存的网址。悬浮窗没有「条目多选」。Ctrl+Enter 仍待定 |

关联用于跳转，以及在悬浮窗里勾选完成。待办完成或进入回收站不改变分组；待办被永久删除后，只自动解除这一条关联，该分组的其他关联不变。第一版里，分组只包含用户拖入的引用，可以是文件、文件夹或网页。一键浏览器扩展更晚，先做 Chrome，见「网页引用」。

**条目多选。** 2026-10-14 决定。只在面板里当前打开的分组的条目列表。文件引用和网页引用同一套。没有「选择」按钮。悬浮窗没有这一套：仍是单击选中一条，Enter 或双击打开，移除只用「移除引用」按钮，没有 Delete 键，也没有右键菜单。

单击一条，只选中这一条。Ctrl+单击切换这一条的选中。Shift+单击从锚点连到这一条，这一段成为选中，段外的选中去掉。同时按着 Ctrl 和 Shift 时，这一段加进已有的选中，段外的选中保留。锚点是上一次普通单击、Ctrl+单击或右键点到的那一条；还没有锚点时，Shift+单击只选中点的这一条。在一行上按下，只有松开时仍在这一行里才算点击。在另一行或列表外松开，不改选中。

选中的条目沿用列表已有的选中底色。锚点那一条保留左侧色条。只选中一条时，底部仍显示这条的路径或网址，以及「打开」「打开所在目录」「移除引用」。选中多条时，底部改为「已选 N 条」，按钮相同。「打开所在目录」在选中里至少有一条路径引用时可用。

双击或 Enter 打开当前选中的条目。文件和文件夹用 Windows Shell 打开；网页引用用默认浏览器打开保存的网址。选中不止一条时，这些动作作用在全部选中的条目上。Ctrl+Enter 对选中的路径引用打开所在目录。网页引用上的 Ctrl+Enter 仍待定。Ctrl+A 选中当前分组里的全部条目。分组多选打开时，Ctrl+A 改为选中全部分组，见「分组多选」。

Delete 移除当前选中的引用。只选中一条时直接移除。多于一条时，底部先换成「移除这 N 条引用」「确认移除」和「取消」。确认之后才删。只删引用，不删除原文件，不关闭、不移动浏览器标签。写盘失败的仍留在选中里，并显示错误。点「取消」只撤回这次确认，选中还在。

右键一条：这一条已经选中时，选中保持不变，锚点改到这一条；没有选中时，改为只选中这一条。然后打开菜单，作用在当前选中上。「打开」打开选中的条目。「打开所在目录」与底部按钮相同。「移除引用」与 Delete 相同。下面列出其他分组的名称，点一个就把选中的引用移到那个分组。条目没有「浮出」。点菜单外面或再按 Esc，菜单关闭，选中还在。

把选中的条目拖到左侧另一个分组上松开，这些引用移到那个分组。只有松开时指针还在窗口里、并且落在某个分组上，才移动。指针离开窗口时清掉分组高亮。这次没有路径可以拖出（只有网页引用，或路径都不存在）时，不开始拖出，之后松开也不把引用移进离开前高亮过的分组。拖的是还没选中的一条时，先改为只选中这一条再拖。指针还在窗口里时不交给资源管理器。指针离开窗口后，选中的路径引用按「拖出文件或文件夹」交给资源管理器：只允许复制和创建快捷方式，不允许移动。网页引用不在这次拖出里，能否拖出仍待定。拖到分组上的移动只改引用所在的分组。目标分组里已经有同一路径时，不新增第二条，来源分组里的这一条去掉。从资源管理器或浏览器拖进来，仍加入当前打开的分组，不看条目选中，也不看分组勾选。

Esc 先关右键菜单，再撤回条目移除的确认，再撤回分组删除的确认，再清掉条目选中，再退出分组多选，最后才收起面板。清掉条目选中不收起面板。

**分组多选。** 2026-10-14 决定。分组列表在有分组时，上方有「选择」。点它进入多选：每一行出现勾选框，列表下方出现操作条，写「已选 N 个」。这个按钮这时显示「完成」，点它退出多选。Esc 在没有菜单、没有确认、也没有条目选中时也退出。退出后勾选框和操作条消失，勾选不保留。退出不收起面板。没有分组时不显示「选择」。

不在多选时，单击一行打开该分组。Ctrl+单击把这一行勾上并进入多选，不换当前打开的分组。Shift+单击从当前打开的分组连到点的这一行，这一段成为勾选，并进入多选。已经在多选时，单击和 Ctrl+单击只切换这一行的勾选，不换当前打开的分组。Shift+单击从锚点连到这一行，这一段成为勾选，段外的勾选去掉。同时按着 Ctrl 和 Shift 时，按 Shift 这一段处理。锚点是上一次普通单击或 Ctrl+单击的那一行。点「选择」时，当前打开的分组是锚点，但不会因此被勾上。在一行上按下，只有松开时仍在这一行里才算点击。

操作条上有「全选」「取消全选」「悬浮」「删除」。「全选」勾上全部分组。「取消全选」去掉全部勾选，仍留在多选。「悬浮」按列表顺序把已勾选的每一个分组打开成悬浮窗；已经打开的只聚焦。「删除」先换成「确认删除」和「取消」，哪怕只勾了一个分组。确认后删除这些分组和其中的引用，不动原文件，也不关闭、不移动浏览器标签。写盘失败的分组仍留在勾选里，并显示错误。没有勾选时「悬浮」和「删除」不可用。全部删除成功后退出多选。

分组多选打开时，右侧仍是当前打开的那一个分组。重命名、上移、下移、关联待办、头部的「悬浮」和「删除分组」仍只作用在这一个分组上。不提供批量重命名、批量排序或批量关联待办。从外面拖入文件或网址，目标仍是当前打开的分组。

**网页引用。** 2026-10-13 决定。排在 v0.2.0 之后。有代码，未在 Windows 上验收。一条网页引用保存网址、标题和网站图标。只保存引用。浏览器里的标签不关闭、不移动，就像文件条目只保存路径、不移动原文件。不把页面正文写进数据目录。

网站图标在条目保存成功之后后台获取，不挡住保存。收纳页或收纳悬浮窗把该条列出来、本地还没有这张图标时也会再取。用默认浏览器打开该条时，若还没有图标，再试一次，不挡住打开。优先使用页面声明的站点图标，取不到时再试站点根上的 `/favicon.ico`。只向 `http` 和 `https` 的地址请求。图标放在数据目录里一份可以整份删掉再重建的缓存，不写进分组文件。获取失败或缓存写不进去时，条目仍在，图标位留空。同一次运行里，因为列表而失败的地址不再反复请求；打开该条会再试一次；进程重启后，缓存里没有就再取。失败不写进磁盘。导出和备份不含这份缓存。导入按白名单替换数据文件时也不删除它。删掉缓存之后，同一条可以再取。搜索结果里的网页引用归入「收纳」组，见「搜索」。使用这份网站图标缓存；还没有时后台再取，失败或尚未取到则图标位留空。

第一版只接受拖进来的网址：地址栏上的锁图标，或从页面里拖出的链接。接受的拖放格式是 `CF_HTML`、纯文本 `CF_UNICODETEXT`、`UniformResourceLocatorW` 和 `text/x-moz-url`。面板的收纳页和收纳分组悬浮窗都接受。没有分组时，与拖入文件相同，先创建名为「收纳」的分组。浏览器链接的这次拖放如果同时带上虚拟的 `.url` 文件（`FileGroupDescriptor` / `FileContents`），不把它存成路径引用，也不复制进数据目录，也不读取 `FileContents`。标题取 `FileGroupDescriptorW` 里这个文件的名字，去掉末尾的 `.url`，不区分大小写。`Cursor Status.url` 的标题是 `Cursor Status`。页面链接的标题是链接文字；2026-10-13 的手测里，它与去掉 `.url` 的文件名相同，`CF_HTML` 的文档标题是空的，不用文档标题。同日的 Chrome 与 Edge 手测里，锁图标和页面链接都没有提供 `text/uri-list`，它不在已接受的格式里。锁图标没有 `CF_HTML`，页面链接有。那次的 href 写在 [roadmap.md](roadmap.md)「技术验证」结论里。

打开该条时，用默认浏览器重新打开保存的网址。面板和悬浮窗里，单击选中，Enter 或双击打开。Ctrl+Enter 仍见下面的待定。移除引用或删除分组只删掉保存的引用，浏览器里的标签保持原样。只有路径引用的旧分组照常打开。搜索结果里会出现这一条，见「搜索」。

**同一网址只保留一条。** 比较前先规范化，只做三步：去掉首尾空白；协议和主机名改成小写；去掉路径末尾的一个 `/`，问号或井号前面的那个也算。`HTTP://Example.COM/a/` 与 `http://example.com/a` 是同一条，`http://example.com/` 与 `http://example.com` 是同一条，`http://example.com/a/?q=1` 与 `http://example.com/a?q=1` 是同一条。路径里其余字符的大小写、`www`、端口、用户名、查询和片段都不改。因此 `http://example.com` 与 `https://example.com` 是两条，`http://example.com/A` 与 `http://example.com/a` 是两条，带片段与不带的是两条。全部收纳里，规范化结果相同的网址只保留先拖入的那一条。再次拖入，包括拖进另一个分组或悬浮窗，不新增，也不改已有条目的网址、标题、图标和所在分组。删掉之后可以再拖入。

一键浏览器扩展排在拖入这一版之后，先做 Chrome。其它浏览器更晚。扩展若要写入收纳，同样只保存引用，不关闭、不移动标签。点一下收的是当前页还是链接、是否走应用页、权限说明怎么写，见待定。

网页引用的以下几点待定：

1. 没有以 `.url` 结尾的 `FileGroupDescriptorW` 文件名时，标题显示什么。标题取该文件名去掉末尾 `.url` 已经定了。页面链接的标题是链接文字，与该文件名相同，也已经定了。这两条不在这项里重开。
2. 一次拖放同时有多种已接受格式时，用哪一个。纯文本要满足什么才算网址。不是网址的纯文本是拒绝并显示错误，还是忽略。
3. 一次拖入多个网址时是否全部保存。同一次拖放里既有真实文件又有网址时，是都保存、只保存文件，还是整次拒绝。浏览器链接拖放里和已接受格式一起带来的虚拟 `.url`（`FileGroupDescriptor` / `FileContents`）已经定了：不存成路径引用，也不复制进数据目录，不在这项里重开。
4. 接受哪些协议。`http` 和 `https` 以外的地址是否拒绝。
5. `CF_TEXT` 是否与 `CF_UNICODETEXT` 同样接受，待定。`UniformResourceLocator`（不带 W 的 ANSI 格式）是否读取，待定。`text/uri-list` 在 2026-10-13 的锁图标和页面链接里都没有出现，是否接受待定。已接受的四种以外，其它拖放格式是否接受，待定。`CF_HTML`、`CF_UNICODETEXT`、`UniformResourceLocatorW` 和 `text/x-moz-url` 已经接受，不在这项里重开。
6. 网页条目上 Ctrl+Enter 做什么。搜索结果上的 Ctrl+Enter 与这一条相同。面板和悬浮窗里，单击选中网页条目、Enter 或双击打开，已经定了，不在这项里重开。文件条目同样是单击选中、Enter 或双击打开。
7. 网页条目能否拖出。能拖出时，对方收到什么。
8. 列表里标题缺失时怎么显示。网站图标与文件条目共用图标位，没有图标时该位留空，已经定了，不在这项里重开。
9. 网址后来打不开时，是否显示与「路径不存在」相当的错误。
10. 一键浏览器扩展：点一下收的是当前页还是某个链接，是否走应用页，权限说明怎么写。先做 Chrome、不关闭、不移动标签，都已经定了，不在这项里重开。面板上没有名为「扩展」的标签，已经定了，不在这项里重开。

悬浮窗的以下几点待定：悬浮入口按钮的位置；悬浮窗里移除引用除按钮外是否还有 Delete 键、右键菜单等触发方式，以及是否需要确认；默认大小和默认位置；分组被删除时已打开的悬浮窗怎么办；单独一个收纳悬浮窗退出再启动后是否恢复。贴边的判定距离、同时贴住两条边时的选择、滑动、收起后拖动、收起时关闭、贴边时改大小、记下的边不再是外侧时怎么办、外沿还是工作区、独占全屏、再次悬浮是否展开，与便签悬浮窗同一份待定，见「便签」。把手的厚度、长度和颜色已经写在「便签」。叠页的未定项也与便签同一份，见「便签」。

关联待办的以下几点待定：多条关联在分组列表、分组详情和待办页标记上的具体显示，标记是否显示数量；悬浮窗「关联待办」的展开状态是否记住；已完成或在回收站里的关联待办在悬浮窗列表里怎么显示；列表的排序；是否可以在悬浮窗里取消完成；「关联待办」标题行是否显示条数和折叠箭头的样子。

**禁止。** 扫描系统正在打开的文件。自动归集。内容搜索。同步。把文件复制进数据目录。绑定真实文件夹。拖出时移动原文件。关闭悬浮窗时删除分组。关闭或移动浏览器标签。把网页正文存进数据目录。在搜索框里输入网址来创建收纳条目。

## 设置

**入口。** 设置标签，或托盘「设置」。

**可见内容与动作。** 2026-10-14 决定。左边一列分类，右边是当前分类的内容。分类顺序固定：常规、待办、数据、其他。

- 常规：开机启动、热角、搜索条热键、主题（明、暗、跟随系统）、网页搜索引擎（Google、必应、百度，默认 Google）。
- 待办：安静时段、处理模式「稍后」天数（1 至 30，默认 3）。
- 数据：数据目录、备份、导出、导入。数据目录显示当前正在使用的目录，可以更换。更换时选择一个文件夹，暂停写入，把现有数据复制到新目录，逐个校验。校验通过后才更新引导文件，然后切换到新目录。界面在切换完成之前仍显示原来的目录。失败时继续用原来的目录，并显示错误。旧目录保留，不自动删除。新目录里已经有 Lanwork 数据时不合并，不迁移。目标不可写或空间不足时不迁移。复制过程中进程结束，下次启动仍用原来的目录。引导文件已经更新之后进程结束，下次启动用校验过的新目录。迁移带走待办、便签、收纳、配置、便携应用与别名和隐藏名单、待办悬浮窗的位置、工具窗口位置和工具存储。大小、贴边、钉住和窗口位置在同一份 `tool-windows/<工具 id>.json` 里。这份文件还不在更换目录时复制的名单里，所以这一步更换目录不会带走它。尚未完成的清除标记随这些数据复制，重启后仍能补上收纳解除。已经发出的提醒记录、网站图标缓存、日志、备份，以及尚未完成的导入留在原来的目录。「备份」右侧是「立即备份」。点了之后要等这次备份完成，列出的备份里才多一份。进行中列表不变。下面列出已有的自动备份和手动备份，合计仍是最多 7 份。一份都没有时显示什么、每一份怎么称呼，仍待定。「导出」选择保存位置。「导入」先显示内容概览，确认后才按下面的规则替换，取消则当前数据不变。概览里写哪些数，仍待定。这一组有操作在进行时，更换、立即备份、导出和导入都不可再点。启动后若这次是从未完成的导入恢复过来的，设置页显示「导入未完成」。导入导出的规则仍是下面几段。
- 其他：「隐藏的应用」、关于与更新（当前版本、检查更新）。

「隐藏的应用」列出搜索里隐藏的应用，每条有「恢复」；没有时显示「没有隐藏的应用」。

安静时段是每天固定的一段，开始和结束各是一个时刻，可以跨过午夜，例如 22:00–08:00。没有这段时不安静。时段内不弹得到期通知；时段结束后的合并补发仍按「待办」。番茄钟的工作时长、休息时长和长休息时长仍按「番茄钟」，不在这四组里。

主题、网页搜索引擎、安静时段和「稍后」天数改完马上按新值生效，重启后仍在。写盘失败时控件回到原值并显示错误。

搜索条热键录入和保存规则相同。主键是 `A`–`Z`、`0`–`9`、`F1`–`F24`、空格（`Space`）、方向键（`Up`、`Down`、`Left`、`Right`）、`Home`、`End`、`PageUp`、`PageDown`、`Insert`、`Delete`、标点符号键（`;`、`=`、`,`、`-`、`.`、`/`、反引号、`[`、`\`、`]`、`'`）、小键盘数字（`Numpad0`–`Numpad9`）和小键盘运算符（`NumpadMultiply`、`NumpadAdd`、`NumpadSubtract`、`NumpadDivide`）。除 `F1`–`F24` 外，主键必须至少带 Ctrl、Alt、Shift、Win 中的一个。`F1`–`F24` 可以单独使用。不带修饰键的普通键无效，不写入配置。配置里已经符合这些规则的热键照常加载。被系统或其他程序占用时仍提示已被占用，不另设黑名单。

已知限制。热键触发时系统不提供扩展键标志。NumLock 关闭时，小键盘数字和对应的导航键分不开：存成 `Numpad4` 的热键不会触发，存成 `Left` 的热键也会被小键盘 4 触发。小键盘 0–3、6–9 和 Insert、End、Down、PageDown、Right、Home、Up、PageUp 同样如此。小键盘 5 在 NumLock 关闭时不会触发存成 `Numpad5` 的热键。录入时用扩展位区分这些键，不读 NumLock。

设置里不另设「应用」页。名叫「应用」的只有面板这一页，见 [tools.md](tools.md)。便携应用、别名和手动刷新的界面入口仍待定。已隐藏的应用仍在设置页的「隐藏的应用」。

设置页显示当前版本。启动之后在后台读取 GitHub 上 `wynxing/Lanwork` 最新正式版的 `latest.json`，之后每过一天再读一次。「检查更新」马上再读一次。这份文件给出稳定版本、安装包文件名和 SHA-256。有 `notes` 时，设置页显示这段发行说明。没有这项时不显示说明，版本和更新仍可用。已经发布的 v0.3.0 没有 `notes`。没有更新时显示「已是最新版本」。有更新时，托盘图标上有一个小标记，设置页显示新版本。不会自动下载，也不会自动安装。

安装版可以点「更新」。程序下载 `Lanwork-Setup-<版本>.exe`，用这份 `latest.json` 里的 SHA-256 核对。通过之后才退出，静默安装，再启动 Lanwork。安装不修改用户数据。校验失败、下载失败或安装起不来时不替换当前程序，并显示错误。安装程序没有成功结束时，下次启动显示「安装失败」。便携版只显示「打开发布页」，打开这个版本的发布页。网络失败时显示「检查更新失败」，不安装。

主题只切换明、暗、跟随系统。亚克力由系统绘制。不提供搜索条、面板或便签的透明度百分比。背景 API 不可用时的纯色见全局规则 7。

每天第一次启动时自动备份一次。自动备份和手动备份合计最多保留 7 份，超出时删除最旧的。

导入先显示内容概览。确认后先备份当前数据，再替换。校验失败时当前数据不变。替换过程中进程中断时，下次启动恢复为导入前的数据，并显示「导入未完成」。导出不含 token、环境变量和日志。尚未完成的清除标记不进入导出和备份，导入也不删除它。

导出包含收纳分组和其中的路径引用，不含被引用的文件。网页引用随分组进入导出和备份，不含页面正文。网站图标缓存在数据目录里，可删除后重建，不进入导出和备份，见「收纳」。待办悬浮窗的位置、贴边和叠页在单独的一份记录里，随导出和备份走，见「待办」。不写进某一条待办或某一个清单。v0.2.0 之后，每个工具的窗口位置、大小、贴边、钉住和该工具自己的存储进入导出和备份，密钥不进入，见 [tools.md](tools.md)。工具副本和启用状态进入导出；这两项是否进入备份，待定。token 仍不进入导出。

**验收。** 左边四个分类是常规、待办、数据、其他。安静时段可以保存跨午夜的 22:00–08:00，并据此判断当前是否在时段内。主题改成明或暗后马上换，重启后仍是。网页搜索改成必应或百度后，结果最后一条和打开的搜索页马上换成该引擎，重启后仍是。「稍后」写成 1 和 30 可以保存，0 和 31 被拒绝并回到原值。写盘失败时这些控件回到原值并显示错误。数据这一组能看到当前数据目录，可以更换并迁移。迁移成功后数据仍在，重启使用新目录，旧目录还在。尚未完成的清除标记在新目录里，重启后仍能补上收纳解除。新目录已有数据时不迁移。目标不可写或空间不足时仍是原来的目录，并显示错误。复制中途结束进程，重启仍用原来的目录。引导文件更新之后结束进程，重启用新目录。非法热键不覆盖原来可用的热键，并显示错误。「立即备份」完成之后能看到多出的一份。进行中列表不变。导入前能看到内容概览，取消后数据不变。校验失败时显示错误，当前数据不变。导入中断后原数据仍可打开，设置页显示「导入未完成」。同一天第二次启动不再自动备份。备份超过 7 份时，删除最旧的，直到不超过 7 份。导出不含尚未完成的清除标记。设置里没有名叫「应用」的页。便携应用、别名和手动刷新的界面入口仍待定。设置页「隐藏的应用」可以恢复已隐藏的应用；恢复后该应用可以再次被搜到。写盘失败时名单不变，并显示错误。设置页可以检查更新。有新版本时能看到版本，`latest.json` 带有发行说明时能看到说明，托盘上有标记。安装版点「更新」后才下载并安装，用户数据仍在。安装没有成功时，下次启动显示「安装失败」。便携版只打开发布页。网络失败时不安装。

## 番茄钟

**入口。** 用户对当前待办启动番茄钟。没有当前待办时不能开始。2026-10-15 决定：这个窗口是「应用」页里的内置工具，用 [tools.md](tools.md) 的悬浮窗外壳和清单格式来写。还没有界面。计时规则以本节为准。可以停用，不能卸载，也没有更新。停用时正在进行的计时停止；再次启用后没有上一次的剩余时间。应用页上的「悬浮窗」只打开窗口，不自动开始计时。没有当前待办时仍可打开，窗口里显示「没有当前待办」。

**可见内容。** 独立小窗。只显示当前待办标题和计时状态。没有当前待办时，标题处显示「没有当前待办」。可关闭、可折叠。窗口不点击穿透。

**动作。** 计时对象始终是当前待办。用户清除当前待办或指定另一条时，本次计时停止。关闭窗口即停止计时。不保存计时记录。

默认工作 25 分钟、休息 5 分钟。工作与休息交替，每完成 4 轮工作后的休息为长休息，默认 15 分钟。工作时长、休息时长和长休息时长都可以在设置里修改。工作时长允许 1 至 120 分钟。休息时长和长休息时长允许 1 至 60 分钟。

暂停冻结剩余时间，之后可以继续。跳过进入下一阶段，本轮不记为完成。完成记为完成一轮并进入休息。暂停、跳过和完成都不改变待办的完成状态。

到点发系统通知。安静时段内不弹出。时段结束后，错过的通知按「待办」中安静时段结束的方式合并补发：多条合成一条，可以展开查看。

**禁止。** 根据前台窗口或打开的文件推断当前待办。云同步。在这个窗口编辑待办列表。

**验收。** 未指定当前待办时无法开始。点「悬浮窗」不自动开始计时。没有当前待办时仍可打开窗口，窗口显示「没有当前待办」。切换当前待办后，窗口不再显示上一条的剩余时间。暂停后再继续，剩余时间与暂停时相同。跳过不增加完成轮数。完成一轮后待办的完成状态不变；满 4 轮后进入长休息。关闭窗口后再打开，没有上一次的剩余时间。安静时段内到点不弹出通知。工作时长只接受 1 至 120 分钟，休息时长和长休息时长只接受 1 至 60 分钟。

## 后续规格

下面三项排在 v0.2.0 之后。网页引用已有代码，未在 Windows 上验收；其余两项还没有代码。与本文已经写明的规则冲突时，以本文为准。

- 收纳中的网页引用，见「收纳」的「网页引用」。2026-10-13 决定。有代码，未在 Windows 上验收。一条保存网址、标题和网站图标，只存引用，不关闭、不移动浏览器标签。标题取虚拟 `.url` 的文件名去掉末尾 `.url`。页面链接的标题是链接文字，与该文件名相同。打开后用默认浏览器重新打开。同一网址在全部收纳里只保留一条。搜索结果归入「收纳」组，使用网站图标缓存，失败或尚未取到则图标位留空。拖入保存后，以及收纳页或收纳悬浮窗列出或打开该条时，后台获取网站图标；失败则图标位留空，条目仍在。缓存可删除后重建，不进入导出和备份。第一版是拖入网址，接受的格式见「网页引用」，收纳悬浮窗同样接受。一键浏览器扩展更晚，先做 Chrome，还没有代码。
- 外部 AI 通过本机 MCP 修改待办和便签，见 [external-ai.md](external-ai.md)。默认关闭，在设置里打开。搜索框仍然只参与搜索。外部修改不加标记。和本机同时改同一条待办时，由用户选择保留哪一版。删除仍进回收站。
- 应用页与自定义悬浮窗工具，见 [tools.md](tools.md)。2026-10-15 决定，同日补充：原先的扩展页并入这一页，面板标签是「应用」，没有「扩展」标签，也不再把番茄钟写成官方插件。应用页有代码，未在 Windows 上验收。导入、卸载、更新、查看权限和番茄钟迁移还没有。悬浮窗外壳可用 `lanwork --float-shell-demo` 打开。宿主在 `crates/toolhost`，没有界面。同日技术验证「工具宿主」通过。凭据管理器界面待用户用 `lanwork --toolhost-cred` 确认，见 [roadmap.md](roadmap.md)。开发说明见 [tool-dev-guide.md](tool-dev-guide.md)。工具卡片上的一行短说明是全局规则 1 的例外。「自定义」为空时同时显示「没有工具」和「导入+」，也是这条规则的例外。番茄钟的计时规则仍以「番茄钟」为准；它是用这套格式写成的内置工具。分类是「内置」和「自定义」。「导入+」只在「自定义」，接受文件夹和 zip，也接受拖入。同一 id 再导入是更新，要先确认；确认框写「保留数据」，并保留存储、密钥、窗口位置、大小、贴边和钉住。导入权限只能整份接受或取消。「查看权限」复用这张卡片，没有「确认」。卸载要确认，并删除该工具的存储和密钥。内置和自定义都有启用开关；关闭时悬浮窗马上关掉，重启后仍是关闭。新导入的工具默认启用。内置工具的「⋯」只有「查看权限」，没有更新，也没有卸载。自定义的「⋯」是「更新」「卸载」「查看权限」。图标是 `icon.png`，没有、读不出或不是 PNG 时用名称的第一个字。脚本超时和脚本错误写成「脚本超时（第 N 行）」「脚本错误（第 N 行）」。点「悬浮窗」只打开窗口，不自动开始计时。没有当前待办时，番茄钟的「悬浮窗」仍可打开，窗口里显示「没有当前待办」；不能开始计时。设置不另设「应用」页。窗口位置、大小、贴边、钉住和工具存储进入导出和备份，密钥不进入。工具副本和启用状态进入导出；这两项是否进入备份，待定。
