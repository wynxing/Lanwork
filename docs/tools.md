# 应用页与自定义悬浮窗工具

本文规定「应用」页、工具悬浮窗外壳，以及自定义工具的可见行为和宿主模型。与 [product.md](product.md) 已经写明的规则冲突时，以 product.md 为准。番茄钟的计时规则以 product.md「番茄钟」为准，issue #59。清单字段、组件和 Lua 调用的写法见 [tool-dev-guide.md](tool-dev-guide.md)。实现状态见 [roadmap.md](roadmap.md)。产品界面还没有代码。宿主在 `crates/toolhost`（包名 `lanwork-toolhost`），没有界面。窗口验证程序仍在 `spikes/toolhost`。

通过标准在 [roadmap.md](roadmap.md)「技术验证」的「工具宿主」。窗口验证程序在 `spikes/toolhost`，不进产品界面。宿主和安全测试在 `crates/toolhost`。Windows 11 桌面上的窗口、空闲采样和凭据管理器界面未测，该项未通过。没有通过记录之前，不写依赖本规格的界面。内存和 CPU 的数字上限仍待定，不宣称已经达到。

2026-10-15 决定。运行时不引入 Vue、Tauri、WebView2，也不用 HTML 或网页视图画工具。工具用宿主自带的 Slint 组件排界面。逻辑用嵌入的 Lua 5.4，库是 `mlua`，放在沙箱里。不引入 cordis 这个库。结构按它的方式：宿主暴露服务，工具在清单里声明要用哪些服务；用户导入时确认；脚本只能调用已经确认的服务。

## 应用页

**入口。** 面板上的「应用」标签。标签顺序是待办、便签、收纳、应用、设置，见 product.md「面板」。没有「扩展」标签。2026-10-15 补充决定：原先的扩展页并入这一页，统一叫「应用」。同日再定：设置里不另设「应用」页。名叫「应用」的只有面板这一页。便携应用、别名和手动刷新不放在这一页，它们的界面入口仍待定，见 product.md「设置」。

**可见内容。** 顶上是分类标签，顺序是「内置」「自定义」。只有这两类。

分类下面是一列工具卡片。每张卡片有名称、一行短说明和「悬浮窗」按钮。短说明由工具作者写在清单里，这是全局规则 1 的例外。卡片上除此之外没有介绍和使用步骤。导入的工具另有「卸载」。内置工具另有「停用」或「启用」，没有「卸载」。

番茄钟在「内置」里，不经过导入。用户导入的工具在「自定义」里。

「导入+」只出现在「自定义」，是这一列的最后一张。它是导入入口，没有短说明。「内置」里没有这张卡片。

当前分类没有工具时，显示「没有工具」。

**动作。**

| 动作 | 结果 |
| --- | --- |
| 分类标签 | 只筛选下面的卡片 |
| 「悬浮窗」 | 只打开该工具的悬浮窗，不自动开始计时。已经打开时，只把焦点给这个窗口，不出现第二个。工具已停用时，这个按钮不可用 |
| 「导入+」 | 开始导入，见「导入」。只在「自定义」里 |
| 「卸载」 | 只在导入的工具上。先确认。确认后关掉它的悬浮窗，删除数据目录里的副本、该工具的存储，以及它在凭据管理器里的密钥。取消则这些都还在 |
| 「停用」 | 只在内置工具上，当前是启用时显示。立即停用：关掉悬浮窗，「悬浮窗」不可用。番茄钟正在计时的，本次计时停止。重启后仍是停用 |
| 「启用」 | 只在内置工具上，当前是停用时显示。启用后可以再开悬浮窗。番茄钟没有上一次的剩余时间 |

没有当前待办时，番茄钟卡片上的「悬浮窗」不可用。2026-10-15 决定：这个按钮只打开窗口，不自动开始计时。计时由窗口里的动作开始。计时对象、没有当前待办就不能开始，仍按产品规格。

**禁止。** 在这一页放功能介绍或使用步骤。用网页视图画这一页。搜索框里的文字不创建工具。卸载内置工具。未确认就卸载。

**验收。** 面板标签是待办、便签、收纳、应用、设置，没有「扩展」。应用页顶上是「内置」和「自定义」。番茄钟在「内置」，卡片上有「停用」，没有「卸载」，也没有「导入+」。切到「自定义」时，导入的工具各占一张卡片，卡片上有名称、一行短说明、「悬浮窗」和「卸载」，最后一张是「导入+」。没有导入的工具时，显示「没有工具」，「导入+」仍在。点「悬浮窗」只打开该工具的窗口，不自动开始计时；已经打开时再点，焦点回到这一个窗口。没有当前待办时，番茄钟的「悬浮窗」点不了。点「卸载」后出现确认；取消则工具、存储和密钥都还在；确认后这三样都没有了，悬浮窗关掉。点番茄钟的「停用」后，它的悬浮窗关掉，正在走的计时停止，重启后仍是停用；再点「启用」后可以打开，没有上一次的剩余时间。

## 悬浮窗外壳

2026-10-15 决定。工具的悬浮窗是同一套外壳。外壳负责窗口，工具换上里面的内容和逻辑。

外壳提供这五件事：

1. 始终在其他普通窗口之上。
2. 可以拖动。
3. 贴边收成把手。规则与便签悬浮窗相同，见 product.md「便签」。那里已经标成待定的项，工具悬浮窗沿用，不在这里另定。
4. 记住位置和大小。关闭后再打开、重启后再打开，用记下的值。不贴边时整扇留在所在显示器的工作区里，规则见 product.md「便签」的「工作区」。贴边时仍按贴边，不拉回工作区。
5. 钉住。钉住和位置、大小一起记住。

窗口不点击穿透。面板收起或失焦时，这个窗口不关闭。关闭窗口只关窗口，不卸载工具。

内容区由清单里的组件画出，宿主用自带的 Slint 组件绘制。组件按清单顺序从上到下排成一列。嵌套、分栏和网格，待定。拖动条、贴边把手和钉住画在内容区外面。钉住控件的位置，待定。

每个工具一份位置、大小、贴边和钉住，记在 Lanwork 数据目录里，不写进工具文件夹。窗口位置进入导出和备份。2026-10-15 决定：大小、贴边、钉住进入导出。这三项是否进入备份，待定。没有记下位置时窗口出现在哪里，默认大小是多少，待定。不在叠里时，重启后会不会自己打开，待定。

便签悬浮窗和待办悬浮窗在概念上能放进这套外壳。它们已经写在产品规格里的行为保持不变：没有钉住按钮，始终在最上层。本文不改那些窗口。以后是否改成由这套外壳承载，待定。

工具悬浮窗能否与便签、收纳、待办悬浮窗落在同一叠，待定。是否显示来源行，待定。

钉住关掉之后，窗口是否离开最上层，以及会不会阻止贴边后失焦收回，待定。

**禁止。** 用 HTML、网页视图或 WebView2 画内容区。在外壳上放说明文字。

## 工具包

一个工具是一个文件夹。文件夹里有一份 TOML 清单，以及清单 `entry` 指向的一个 Lua 入口脚本。界面布局写在这份清单里，不另放界面描述文件。字段见开发说明。

逻辑由宿主用 `mlua` 嵌入 Lua 5.4 执行。每个工具一块独立的 Lua 状态。一个工具不能调用另一个工具的服务，也不能读到另一个工具的存储或密钥。

脚本在沙箱里。标准库只放入开发说明列出的那一部分。没有 `io`、`os`、`package`、`debug`。不能加载工具文件夹以外的文件，不能加载本机动态库，不能启动进程。宿主不执行工具文件夹里的可执行文件。协程不放入：超时钩子按 Lua 线程安装，协程是另一条线程，钩子管不到。`require` 和多个 Lua 文件是否允许，待定。入口脚本以外的 `.lua` 文件不执行。

内置工具随程序提供。番茄钟的 id 是 `lanwork.pomodoro`。导入的工具不能使用 `lanwork.` 前缀，否则不安装，并显示「清单无效」。

2026-10-15 决定：图标文件是 PNG。文件名是工具文件夹里的 `icon.png`，和清单放在一起。没有这个文件、文件读不出来或内容不是 PNG 时，卡片用名称去掉首尾空白后的第一个字，不因此拒绝安装。其它图片格式这一版不作为图标。

清单里出现本文和开发说明没有列出的字段、不认识的组件或不认识的服务时，不安装，并显示「清单无效」。版本字段的名字、当前号，以及不认识的版本是拒绝还是兼容读取，待定。在这确定之前，清单不写版本字段；写了会因不认识的字段被拒绝。

## 服务

第一批服务如下。工具在清单的 `services` 里声明。界面上每条是一句白话，不显示内部标识。

| 服务 | 界面句子 | 允许 |
| --- | --- | --- |
| `timer` | 定时刷新 | 按脚本登记的秒数，到期后调用脚本给出的函数。到点之前不调用。间隔最短 30 秒 |
| `notify` | 发送通知 | 发一条系统通知。安静时段内不弹出；时段结束后，错过的多条按产品规格「待办」合并补发 |
| `storage` | 保存这个工具自己的数据 | 按键读写这个工具自己的文本。不存放密钥 |
| `todo.read` | 读取你的待办 | 读取待办，含已完成和当前标记，不含回收站 |
| `todo.complete` | 完成你的待办 | 走现有的完成。带周期的按产品规格生成下一次。不能取消完成、新建、改标题或删除 |
| `http` | 每个域名一句「访问 <主机名>」 | 只向清单里列出、且用户确认过的主机名发请求。第一批纳入的是 `https` 的 GET |
| `secret` | 每个密钥一句「使用你填写的<名称>」 | 用户在工具设置里填写。值放进 Windows 凭据管理器。脚本不能读取原文 |

`http` 不另显示一句「联网」。确认时看到的是逐条主机名。`secret` 确认时只出现名称，不出现值。

第一批纳入的请求是 `https` 的 GET，额度示例用的就是这一种。POST 等其它方法不发送，显示「不在范围内」。这些方法以后是否纳入，待定。不附带密钥的明文 `http` 是否允许，待定。附带密钥时只允许 `https`；不是 `https` 就不发送，显示「地址无效」，避免密钥走明文。`http` 与 `https` 以外的协议不发送，显示「地址无效」。

主机名与清单里某一条忽略大小写相等才发送。`api.example.com` 只等于它自己，不包含 `example.com`，也不包含下一级主机名。路径不另做限制。跳转到清单以外的主机名时不跟随，不发往那个地址，显示「域名未允许」。同一主机名之内是否跟随重定向，待定。主机名写成 IP、或在域名里写端口、路径、通配符时，清单无效。

脚本用密钥的 id 告诉宿主把它放进哪个请求头、前面加什么字。宿主拼好之后发出。脚本读不到拼好的头，也读不到密钥原文。主机名必须已确认。发出请求的那次脚本调用不等待网络；连接和读取在宿主侧完成，有单独的等待上限，秒数仍待定。

授予 `todo.read` 时，待办变更之后宿主调用脚本的 `on_todos_changed`。脚本再自己读。这个回调不写入。

`todo.complete` 走现有待办命令。与本机同时修改同一条时不覆盖，悬浮窗显示「待办保存冲突」。脚本不接触修订号。宿主使用当前已保存的修订号。本机还有未写盘的修改时，同样不覆盖。

便签的读取和写入，以及待办的新建、修改、取消完成、软删除，都放在第二批。第一批不提供收纳、文件内容、配置、备份、启动应用和设为当前。设为当前会停掉番茄钟，这条保持不变。

`notify.send` 一律遵守安静时段，内置工具和导入的工具同一套：安静时段内不弹出；时段结束后，错过的多条按产品规格「待办」合并成一条，可以展开查看。

`storage` 的文本不写入工具文件夹，进入导出和备份。单条大小和键的数量，待定。密钥不进 `storage`。

一次 Lua 回调从进入到返回最长 1 秒。超过则中止这次调用。脚本用 `pcall` 接住这次中止后，钩子仍会在后续检查里继续报错，这次回调不能接着跑完。`xpcall` 的处理函数由宿主在被保护函数返回之后调用，超时钩子仍然开着；处理函数里的死循环同样中止。悬浮窗显示「脚本超时」和行号，不含密钥。已经登记、尚未触发的定时器还在。宿主重画计时组件不占这 1 秒，也不算定时刷新。等网络也不占这 1 秒：套接字不在这条 Lua 调用里。

`string.find`、`string.match`、`string.gmatch`、`string.gsub` 的模式匹配在宿主里按 Lua 5.4 的规则执行。匹配过程中计数，大约每 4096 步对照这次回调的 1 秒截止时间。到点则与钩子一样中止，窗口显示「脚本超时」，`pcall` 不能把这次回调留住。文本和模式仍有临时的长度上限。`string.rep` 的结果也有临时上限；超过则这次调用报错，`pcall` 可以接住，回调继续。`gsub` 的结果缓冲区在每次扩容前计入同一块临时内存预算；各层还没交还的缓冲区加在一起算。超过则这次调用报错，`pcall` 可以接住，回调继续。复制进结果的字节大约每 64 KiB 再对照这 1 秒，到点与钩子一样中止。这四个模式函数同时嵌套最多 8 层，超过则这次调用报错，`pcall` 可以接住。到顶之后，这次调用展开完之前不能再进。`xpcall` 和 `table.sort` 从宿主再进 Lua 时还有重入上限，到顶之后同样要等这次调用展开完。这些字节数和层数仍待定，见「待定」第 2 条，不是产品规则。

`table.sort` 带比较函数时，每次比较都回到 Lua，超时钩子仍然有效。不带比较函数时，比较在 C 里完成；验证程序在元素过多时直接拒绝这次调用。`table.concat`、`string.format`、`string` 的大小写和反转、`utf8` 的长度按文本长度线性完成。`string.format` 的宽度最多两位数字。它们受临时内存上限约束。这些字节数和元素个数不是产品规则。

`timer.every` 的秒数最短是 30。短于 30 则不登记，显示「间隔过短」。`timer.after` 的秒数必须是正数，最短是多少，待定。两者都不是正数则不登记，显示「参数无效」。睡眠或关机期间如何补，待定。

## 组件

第一批组件：文本 `text`、按钮 `button`、计时 `timer`、进度条 `progress`、列表 `list`、输入 `input`、开关 `toggle`。

界面组件 `timer` 显示剩余秒数，由宿主逐秒重画。脚本用 `ui.timer` 设定秒数。组件正在倒数并走到 0 时，宿主调用 `on_timer`。把秒数改成 0，或把倒数停下，都不因此调用。再次设定秒数会换掉上一次倒数。这条回调受 1 秒上限，不受 30 秒刷新下限。显示格式待定。服务 `timer` 只负责定时刷新，不负责把这个组件每秒减一。

每个组件在一个工具里有自己的 id。脚本按 id 改显示，按钮、列表、输入和开关把动作交回脚本。属性和函数见开发说明。

进度条的值按 0 到 1。小于 0 按 0，大于 1 按 1。计时组件小于 0 的秒数按 0。

输入框在中文输入法组合未上屏时，不把未上屏的字交给脚本。上屏之后的文本变化会调用脚本。每个键都调用，还是停一段时间再调用，待定。Enter 是否另有提交，待定。

## 导入

**入口。** 「自定义」里的「导入+」。点它可以选择一个文件夹，或一个 zip。把文件夹或 zip 拖到「自定义」页上，包括拖到「导入+」上，同样开始这一条导入。拖到「内置」上不开始导入。

**格式。** 文件夹和 zip 都接受。文件夹里要有清单。zip 的根上要有清单，或者 zip 里只有一个顶层文件夹、清单在那个文件夹里。两种都先读清单，再进入确认。示例的写法见开发说明，是一个文件夹里的清单和入口脚本。

**可见内容。** 读到清单后，列出工具名称、一行短说明，以及「服务」里的那些白话句子。同一 id 已经安装时，标明这是更新。不能在这一页上改清单。

**动作。** 用户确认这些句子之后才安装。确认是必须全部接受，还是可以去掉几条，待定。未确认则不安装，数据目录里不留下这份新工具；若是更新，已安装的那一份保持不动。正在等待确认时再拖入或再点「导入+」，不开始第二次。

安装把副本放进 Lanwork 数据目录。子目录名，待定。程序使用这份副本。不移动、不删除用户原来的文件夹。不写入 MayDolist 的目录。2026-10-15 决定：新导入的工具默认启用。启用状态进入导出。

同一 id 已经安装时，再导入视为更新，必须先经过上面的确认。确认后用新副本替换旧副本。未确认则不替换。2026-10-15 决定：更新之后，同一 id 已有的窗口大小、贴边和钉住保留。存储、密钥和窗口位置在更新时保留还是清空，待定。

内置工具不走「导入+」，也不再问一次权限。清单里声明的服务就是它能调用的。停用和卸载见「应用页」。

**禁止。** 未确认就写入数据目录。导入时读取收纳里的文件内容，或执行工具里的程序。把密钥写进副本。未确认就替换已安装的工具。

**验收。** 点「导入+」选择一个含清单的文件夹，或一个根上有清单的 zip，或把其中一种拖到「自定义」页上，都先看到名称、短说明和白话句子，句子里有申请的域名，没有密钥的值。确认之后，「自定义」里多出这张卡片。未确认时列表不变，数据目录里没有它，原来的文件夹还在。同一 id 再导入时，确认页标明是更新；取消则卡片仍是原来的那一份；确认后卡片用新清单里的名称和短说明。拖到「内置」上不出现确认页。id 以 `lanwork.` 开头的不安装，并显示「清单无效」。清单里写了不认识的服务时不安装。

## 密钥

工具可以在清单里声明若干密钥。每一项有 id 和设置里显示的名称。用户在该工具的设置里填写。值写入 Windows 凭据管理器，按工具 id 和密钥 id 分开，两个工具的同名密钥不混在一起。凭据的目标名字符串，待定。

值不出现在工具文件、导出、备份和日志里。日志沿用现有对密钥形态的删节。错误文字、请求失败的说明和脚本能读到的返回值里都不放密钥原文，也不放已经拼进请求头的值。

脚本不能读取原文，也没有返回原文的函数。它只能在 `http` 请求里用 id 指明附上哪一个。还没填写就附带这个 id 时，不发请求，显示「未填写密钥」。

宿主只看清单里已确认主机返回的正文和响应头。这是尽力检查：密钥被拆开、加密，或用下面没有列出的写法写出来，仍然可能漏过去。

交给脚本之前，在正文和每一个响应头上检查这些形式。任一命中，正文改成空字符串，`ok` 为假，说明是「请求失败」，状态码仍保留。不把响应头放进返回值。命中即整段清空，不做逐段替换。

检查的形式：

- 密钥原文
- `Bearer ` 加原文，以及 `bearer ` 加原文
- 这次实际发出的请求头的值（前缀加原文）
- 上面每一项的标准 Base64 和 URL 安全 Base64，带末尾填充和不带填充。不按编码长短丢弃。短密钥的编码可能只有几个字符，正文里碰巧出现同样的几个字符时也会整段清空。这是宁可误伤，也不漏掉上面承诺的形式。不在写入时另加最短长度：规格没有最短长度，短密钥仍然要能被认出来
- 把正文或响应头里的 `%XX` 按十六进制解码后再找上面的明文和 Base64。`%` 后两位忽略大小写。未保留字节也可以编码，可以只编码其中一部分。连续解码最多四次。原文或解码结果里的 `+` 再按空格看一次

脚本能读到的返回值里没有这些内容。

设置里是否回显已保存的值、有没有「清除」，待定。除密钥以外，工具设置还能放哪些控件，待定。

## 内置番茄钟

第一个用这套格式写成的内置工具是番茄钟，用来验证外壳、清单和沙箱。id 是 `lanwork.pomodoro`。计时对象、阶段、时长、暂停、跳过、完成、关闭即停止、不保存计时记录、到点通知和安静时段，都按 product.md「番茄钟」和 issue #59。不另写一套时长。工作时长、休息时长和长休息时长仍在设置里，范围仍是 1 至 120 分钟和 1 至 60 分钟。

这个工具声明 `notify` 和 `todo.read`。不声明 `timer`、`storage` 和 `todo.complete`。剩余时间由计时组件倒数，走到 0 时走 `on_timer`，不使用短于 30 秒的定时刷新。暂停、跳过和完成都不改变待办的完成状态。关闭窗口或 `on_unload` 时丢掉本次剩余时间和轮数，不写盘，不进入导出。

没有当前待办时不能开始。清除当前待办或指定另一条时，本次计时停止，窗口不再显示上一条的剩余时间。

产品规格写这个窗口可关闭、可折叠，可见内容是当前待办标题和计时状态。外壳的关闭和贴边把手对应其中的关闭和折叠到哪一步，待定。暂停、跳过和完成在窗口上用什么控件，产品规格没有写。开发说明的示例用三个按钮把这三个动作接出来，是为了走通第一批组件。这些按钮是否超出「只显示标题和计时状态」，待定。

原先的扩展页已并入本页。番茄钟只作为这里的内置工具，不再另有一套官方插件。计时规则只以产品规格为准。

宿主只向 id 为 `lanwork.pomodoro` 的这块状态提供读取三项时长的函数。其它工具没有这个函数，也不能读取配置。

## 安全模型

1. 工具代码只以沙箱里的 Lua 5.4 运行。宿主不加载工具自带的动态库和可执行文件，不用网页视图。
2. 脚本能碰到的服务就是清单里声明、并且用户已经确认的那些。内置工具以随程序提供的清单为准，不再问一次。
3. 未授予的服务不放进这块 Lua 状态。
4. `http` 只向已确认的主机名发送。第一批纳入的是 `https` GET。附带密钥的请求只走 `https`。
5. 密钥只在 Windows 凭据管理器里。工具文件、导出、备份、日志、错误文字和脚本可见的返回值都不含原文，也不含已经附上密钥的请求头。已确认主机的响应若对上「密钥」里列出的形式，正文清空并显示「请求失败」。这是尽力检查。
6. 一个工具的 Lua 状态、存储和密钥与另一个工具分开。
7. 第一批写入只有 `todo.complete` 和 `storage`。完成走现有命令，不能永久删除。便签和其它写入不在第一批。
8. 数据放在 Lanwork 自己的数据目录。不读写 MayDolist 的目录。
9. 搜索框里的字符不创建待办、便签或工具。番茄钟不把计时记录写入数据文件。

## 验收

应用页的分类只有「内置」和「自定义」。「导入+」只在「自定义」。导入文件夹或 zip，以及拖入「自定义」，都先看到白话句子和主机名，确认后才出现卡片；未确认则不出现。同一 id 再导入要先确认，确认后才换成新副本。卸载要先确认，确认后副本、存储和密钥都没有了。内置工具可以停用，不能卸载。

额度示例的窗口里有一行文本和一条进度条。打开时请求一次，之后每 5 分钟再请求。请求的主机名就是确认过的那一条。没填密钥时不发请求，窗口上是「未填写密钥」。脚本侧拿不到密钥。服务端把密钥回显在正文或响应头里时，只要对上「密钥」列出的形式（含百分号编码的未保留字节、只编码一部分、十六进制大小写混合），脚本看到的正文是空的，窗口上是「请求失败」。导出里有这个工具的副本、启用状态、窗口位置、大小、贴边、钉住和存储，没有密钥。大小、贴边、钉住、副本和启用状态是否进入备份，待定。日志里也没有密钥。安静时段内，这个工具的通知不弹出。新导入的这个工具是启用的。没有 `icon.png` 时，卡片用名称的第一个字。

番茄钟在「内置」里，用同一套外壳打开。始终在其他普通窗口之上，可以拖动，贴边收成把手，记住位置和大小，并且有钉住。没有当前待办时不能开始。暂停后再继续，剩余时间与暂停时相同。跳过不增加完成轮数。完成一轮后待办的完成状态不变；满 4 轮工作后进入长休息。关闭窗口后再打开，没有上一次的剩余时间。安静时段内到点不弹出通知。切换当前待办后，不再显示上一条的剩余时间。脚本不每秒被调用；计时组件自己倒数。登记短于 30 秒的定时刷新会被拒绝。一次回调超过 1 秒时，即使脚本用 `pcall` 接住，窗口仍显示「脚本超时」和行号。`xpcall` 的处理函数超时同样如此。脚本错误也带行号。

导出再导入之后，工具副本、启用状态、窗口的位置、大小、贴边、钉住和该工具的存储还在。大小、贴边、钉住、副本和启用状态是否随备份走，待定。密钥不在导出里，也不在备份里。点番茄钟卡片的「悬浮窗」只打开窗口，不自动开始计时。

两项验收都还没有在 Windows 上执行。嵌入 Lua、凭据管理和悬浮窗外壳有验证程序，Windows 屏幕检查未测，该项未通过。见 [roadmap.md](roadmap.md)。

## 待定
