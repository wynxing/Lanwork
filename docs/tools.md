# 应用页与悬浮窗工具

本文规定「应用」页、工具悬浮窗外壳，以及工具的可见行为和宿主模型。与 [product.md](product.md) 已经写明的规则冲突时，以 product.md 为准。清单字段、组件和 Lua 调用的写法见 [tool-dev-guide.md](tool-dev-guide.md)。实现状态见 [roadmap.md](roadmap.md)。应用页有代码，未在 Windows 上验收。导入、卸载、更新、查看权限和填写密钥有代码，未在 Windows 上验收。副本这一版在数据目录的 `tools/<工具 id>/`，路径仍待定。悬浮窗外壳可用 `lanwork --float-shell-demo` 打开。宿主在 `crates/toolhost`（包名 `lanwork-toolhost`），没有界面。窗口验证程序在 `spikes/toolhost`。

通过标准在 [roadmap.md](roadmap.md)「技术验证」的「工具宿主」。窗口验证程序在 `spikes/toolhost`，不进产品界面。2026-10-15 该项通过。凭据管理器界面待用户用 `lanwork --toolhost-cred write|list|clear` 确认。内存和 CPU 的数字上限仍待定，不宣称已经达到。

2026-10-15 决定。运行时不引入 Vue、Tauri、WebView2，也不用 HTML 或网页视图画工具。工具用宿主自带的 Slint 组件排界面。逻辑用嵌入的 Lua 5.4，库是 `mlua`，放在沙箱里。不引入 cordis 这个库。结构按它的方式：宿主暴露服务，工具在清单里声明要用哪些服务；用户导入时确认；脚本只能调用已经确认的服务。

## 应用页

**入口。** 面板上的「应用」标签。标签顺序是待办、便签、收纳、应用、设置，见 product.md「面板」。没有「扩展」标签。2026-10-15 补充决定：原先的扩展页并入这一页，统一叫「应用」。同日再定：设置里不另设「应用」页。名叫「应用」的只有面板这一页。便携应用、别名和手动刷新不放在这一页，它们的界面入口仍待定，见 product.md「设置」。

**可见内容。** 一列工具卡片。每张卡片有图标、名称、一行短说明、「悬浮窗」按钮、启用开关和「⋯」。短说明由工具作者写在清单里，这是全局规则 1 的例外。卡片上除此之外没有介绍和使用步骤。2026-10-15 决定：图标文件是工具文件夹里的 `icon.png`，和清单放在一起。没有这个文件、读不出来或内容不是 PNG 时，用名称去掉首尾空白后的第一个字，不因此拒绝安装。其它图片格式这一版不作为图标。

「导入+」是这一列的最后一张。它是导入入口，没有短说明，也没有启用开关和「⋯」。没有工具时只显示这张卡片，不显示「没有工具」。

**动作。**

| 动作 | 结果 |
| --- | --- |
| 「悬浮窗」 | 打开该工具的悬浮窗。已经打开时，只把焦点给这个窗口，不出现第二个。启用开关关闭时，这个按钮不可用 |
| 「导入+」 | 开始导入，见「导入」 |
| 「⋯」 | 打开这一张卡片的菜单：「更新」「卸载」「查看权限」。声明了密钥的工具再加「填写密钥」 |
| 「更新」 | 为这一张卡片选择文件夹或 zip。包内 id 不是这张卡片时，显示「不是这个工具的更新包」，不打开确认，也不导入。id 相符时按「导入」处理 |
| 「卸载」 | 先确认，确认框写「会删除这个工具的存储和密钥。」确认后关掉它的悬浮窗，删除数据目录里的副本、该工具的存储、`tool-windows/<工具 id>.json`，以及它在凭据管理器里的密钥。取消则这些都还在 |
| 「查看权限」 | 打开与导入确认相同的卡片：名称、一行短说明，以及「服务」里的那些白话句子。没有「确认」。关掉这张卡片不改变已经授予的服务 |
| 「填写密钥」 | 只在清单里声明了密钥的工具上出现。弹出与导入确认同一风格的小窗：工具名称，每个密钥一行。左边是清单里的名称，右边是掩码输入，不回显已保存的值，也不显示密钥 id。关掉再打开时输入是空的，不会把上次填的字带到另一个工具。可以保存或清除。保存只把填写了的行写入 Windows 凭据管理器，空着的行保持原样。某一行没有写上时停在这一行，界面写「「名称」没有写下」，不含密钥的值；已经写上的行仍然生效，开着的窗口重载。清除删掉这个工具已声明的密钥，不再询问一次。脚本不能读取原文。已经打开的悬浮窗在保存或清除之后用上新的值。取消则不改 |
| 启用开关 | 每张卡片都有。关闭时立即停用：关掉悬浮窗，「悬浮窗」不可用。重启后仍是关闭。再次打开后可以再开悬浮窗 |

**禁止。** 在这一页放功能介绍或使用步骤。用网页视图画这一页。搜索框里的文字不创建工具。未确认就卸载。逐条勾选导入权限。

**验收。** 面板标签是待办、便签、收纳、应用、设置，没有「扩展」。应用页是一列卡片，最后一张是「导入+」。没有工具时只显示「导入+」，不显示「没有工具」。每张工具卡片上有图标、名称、一行短说明、「悬浮窗」、启用开关和「⋯」。「⋯」里是「更新」「卸载」「查看权限」；这份工具声明了密钥时还有「填写密钥」。有 `icon.png` 时图标用这张图；没有、读不出或不是 PNG 时，用名称去掉首尾空白后的第一个字。点「悬浮窗」打开该工具的窗口；已经打开时再点，焦点回到这一个窗口。启用开关关闭时「悬浮窗」点不了，已经打开的窗口马上关掉，重启后开关仍是关闭。点「卸载」后出现确认，上面有「会删除这个工具的存储和密钥。」；取消则工具、存储、密钥和窗口记录都还在；确认后副本、存储、密钥和 `tool-windows/<工具 id>.json` 都没有了，悬浮窗关掉。没有声明密钥的工具不出现「填写密钥」。声明了密钥时，「⋯」里有「填写密钥」：每一行是掩码输入，不回显已保存的值，关掉再打开是空的；保存后空着的行不变，填写了的行写入凭据管理器；某一行没有写上时提示「「名称」没有写下」，已经写上的行仍然生效；清除删掉已声明的密钥。保存或清除之后，已经打开的窗口用上新的值。额度示例没填密钥时窗口上是「未填写密钥」；填上并保存后，这句不再留在已经打开的窗口里。「查看权限」打开的卡片与导入确认相同，没有「确认」，关掉之后授予不变。

## 悬浮窗外壳

2026-10-15 决定，2026-10-16 补定外观和状态。工具的悬浮窗是同一套外壳。外壳负责窗口，工具换上里面的内容和逻辑。

外壳提供这五件事：

1. 钉住开着时，始终在其他普通窗口之上。钉住关掉时，是普通窗口层级。没有记下钉住时，按开。
2. 可以拖动。顶部一条细拖动条，高度 28 逻辑像素，与便签悬浮窗的拖动区相同。拖动条右侧是钉住和关闭，各 28×28 逻辑像素，描边和悬停与便签悬浮窗的关闭相同。钉住在关闭左边。不画来源行。
3. 贴边收成把手。规则与便签悬浮窗相同，见 product.md「便签」。那里已经标成待定的项，工具悬浮窗沿用，不在这里另定。贴边后失焦收回与便签相同，钉住开或关都不改变这条。
4. 记住位置和大小。关闭后再打开、重启后再打开，用记下的值。不贴边时整扇留在所在显示器的工作区里，规则见 product.md「便签」的「工作区」。贴边时仍按贴边，不拉回工作区。可以拖边改大小。最小 200×120 逻辑像素，与便签相同。
5. 钉住。钉住和位置、大小、贴边一起记住。

窗口不点击穿透。不出现在任务栏。失去焦点后的半透明磨砂与便签悬浮窗相同，见 product.md 全局规则 7。面板收起或失焦时，这个窗口不关闭。关闭窗口只关窗口，不卸载工具。

没有记下位置和大小时，出现在主屏工作区的右下角，与工作区右缘和下缘各留 24 逻辑像素。默认大小用工具声明的尺寸；清单没有声明时是 320×360 逻辑像素。声明小于最小尺寸时，用最小尺寸。

内容区由清单里的组件画出，宿主用自带的 Slint 组件绘制。组件按清单顺序从上到下排成一列。嵌套、分栏和网格，待定。拖动条、贴边把手、钉住和关闭画在内容区外面。

每个工具一份记录，在数据目录的 `tool-windows/<工具 id>.json`。id 的规则与数据文件的 id 相同。不写进工具文件夹，也不是安装副本的路径；安装副本的路径仍待定。记录里有 `schemaVersion`、可选的 `floatWindow`（`x`、`y`、`width`、`height`）、可选的 `floatDock`、可选的 `floatPinned`，以及 `open`。`floatPinned` 缺了按开，写出的 `false` 是明确关掉。`open` 为真表示退出时这个窗口开着，下次启动再打开。关掉窗口写成假。`floatWindow` 这个字段在、但坐标读不出时，不把它当成没有位置：记下的贴边仍用，并且这次自动打开不覆盖原文件。没有 `floatStack`：工具窗口不与便签、收纳、待办落在同一叠。

窗口位置、大小、贴边和钉住进入导出，也进入备份，字段相同。`open` 只在这份窗口记录里，用来重启后重新打开，不进入导出和备份。`tool-windows/<工具 id>.json` 进入导出白名单和备份白名单；包里的这份把 `open` 写成没有，恢复后窗口不因此自动打开。更换数据目录时按磁盘上的原文件复制，`open` 仍在。

便签悬浮窗、收纳悬浮窗和待办悬浮窗用同一套外壳画拖动条、关闭和贴边把手，里面只换内容。外观仍按产品规格：没有钉住按钮，始终在最上层，拖动条下面有来源行，并且可以叠在一起。工具窗口仍是钉住和关闭、不画来源行、不进这一叠。钉住按钮由外壳的开关控制，工具开着，这三扇关掉。来源行只有这三扇打开。位置仍记在原来的便签文件、分组文件和 `todo-float.json` 里，不改成 `tool-windows/`。旧的 `floatPinned` 仍能读入并丢掉，不再写回。

调试时可以用隐藏命令 `lanwork --float-shell-demo` 打开一个内容是「示例」的外壳窗口。这不是产品入口，也不是已安装的工具。记录 id 是 `lanwork.float-shell-demo`。已经有 Lanwork 在运行时，这条命令不会打开窗口，要先退出。

**禁止。** 用 HTML、网页视图或 WebView2 画内容区。在外壳上放说明文字。给工具窗口加来源行。把工具窗口放进便签、收纳、待办的叠。

## 工具包

一个工具是一个文件夹。文件夹里有一份 TOML 清单，以及清单 `entry` 指向的一个 Lua 入口脚本。界面布局写在这份清单里，不另放界面描述文件。字段见开发说明。可选的 `icon.png` 和清单放在一起，见「应用页」。清单不因此增加字段；不认识的字段仍拒绝安装。

逻辑由宿主用 `mlua` 嵌入 Lua 5.4 执行。每个工具一块独立的 Lua 状态。一个工具不能调用另一个工具的服务，也不能读到另一个工具的存储或密钥。

脚本在沙箱里。标准库只放入开发说明列出的那一部分。没有 `io`、`os`、`package`、`debug`。不能加载工具文件夹以外的文件，不能加载本机动态库，不能启动进程。宿主不执行工具文件夹里的可执行文件。协程不放入：超时钩子按 Lua 线程安装，协程是另一条线程，钩子管不到。`require` 和多个 Lua 文件是否允许，待定。入口脚本以外的 `.lua` 文件不执行。

工具 id 不能以 `lanwork.` 开头。比较忽略大小写，`Lanwork.tool` 和 `LANWORK.x` 也不行。这是保留前缀。以它开头的不安装，并显示「清单无效」。日志里的说明仍是「id 不能以 lanwork. 开头」。

清单里出现本文和开发说明没有列出的字段、不认识的组件或不认识的服务时，不安装，并显示「清单无效」。版本字段的名字、当前号，以及不认识的版本是拒绝还是兼容读取，待定。在这确定之前，清单不写版本字段；写了会因不认识的字段被拒绝。

## 服务

第一批服务如下。工具在清单的 `services` 里声明。界面上每条是一句白话，不显示内部标识。

| 服务 | 界面句子 | 允许 |
| --- | --- | --- |
| `timer` | 定时刷新 | 按脚本登记的秒数，到期后调用脚本给出的函数。到点之前不调用。间隔最短 30 秒 |
| `notify` | 发送通知 | 发一条系统通知。安静时段内不弹出；时段结束后，错过的多条按产品规格「待办」合并补发 |
| `storage` | 保存这个工具自己的数据 | 按键读写这个工具自己的文本。不存放密钥 |
| `todo.read` | 读取你的待办 | 读取待办，含已完成和当前标记，不含回收站 |
| `todo.complete` | 完成你的待办 | 走现有的完成。带周期的按产品规格生成下一次。不能取消完成、新建、改标题或删除 |
| `http` | 每个域名一句「访问 <主机名>」 | 只向清单里列出、且用户确认过的主机名发请求。第一批纳入的是 `https` 的 GET |
| `secret` | 每个密钥一句「使用你填写的<名称>」 | 用户在工具设置里填写。值放进 Windows 凭据管理器。脚本不能读取原文 |

`http` 不另显示一句「联网」。确认时看到的是逐条主机名。`secret` 确认时只出现名称，不出现值。

第一批纳入的请求是 `https` 的 GET，额度示例用的就是这一种。POST 等其它方法不发送，显示「不在范围内」。这些方法以后是否纳入，待定。不附带密钥的明文 `http` 不发送，已经定了。窗口显示「明文 http（是否允许仍待定）」。附带密钥时只允许 `https`；不是 `https` 就不发送，显示「地址无效」，避免密钥走明文。`http` 与 `https` 以外的协议不发送，显示「地址无效」。

主机名与清单里某一条忽略大小写相等才发送。`api.example.com` 只等于它自己，不包含 `example.com`，也不包含下一级主机名。路径不另做限制。主机名不在已确认的清单里时不发送，显示「域名未允许」。重定向一律不跟随，已经定了，同一主机名之内也不跟随。不读取 `Location`，也不发第二次请求。状态码是 3xx 时显示「请求失败」。主机名写成 IP、或在域名里写端口、路径、通配符时，清单无效。IP 是否允许仍待定。

脚本用密钥的 id 告诉宿主把它放进哪个请求头、前面加什么字。宿主拼好之后发出。脚本读不到拼好的头，也读不到密钥原文。主机名必须已确认。发出请求的那次脚本调用不等待网络；连接和读取在宿主侧完成，有单独的等待上限，秒数仍待定。

授予 `todo.read` 时，待办变更之后宿主调用脚本的 `on_todos_changed`。脚本再自己读。这个回调不写入。

`todo.complete` 走现有待办命令。与本机同时修改同一条时不覆盖，悬浮窗显示「待办保存冲突」。脚本不接触修订号。宿主使用当前已保存的修订号。本机还有未写盘的修改时，同样不覆盖。

便签的读取和写入，以及待办的新建、修改、取消完成、软删除，都放在第二批。第一批不提供收纳、文件内容、配置、备份、启动应用和设为当前。

`notify.send` 一律遵守安静时段：安静时段内不弹出；时段结束后，错过的多条按产品规格「待办」合并成一条，可以展开查看。

`storage` 的文本不写入工具文件夹，进入导出和备份。单条大小和键的数量，待定。密钥不进 `storage`。

一次 Lua 回调从进入到返回最长 1 秒。超过则中止这次调用。脚本用 `pcall` 接住这次中止后，钩子仍会在后续检查里继续报错，这次回调不能接着跑完。`xpcall` 的处理函数由宿主在被保护函数返回之后调用，超时钩子仍然开着；处理函数里的死循环同样中止。悬浮窗显示「脚本超时（第 N 行）」，N 是行号，不含密钥。已经登记、尚未触发的定时器还在。宿主重画计时组件不占这 1 秒，也不算定时刷新。等网络也不占这 1 秒：套接字不在这条 Lua 调用里。

`string.find`、`string.match`、`string.gmatch`、`string.gsub` 的模式匹配在宿主里按 Lua 5.4 的规则执行。匹配过程中计数，大约每 4096 步对照这次回调的 1 秒截止时间。到点则与钩子一样中止，窗口显示「脚本超时（第 N 行）」，`pcall` 不能把这次回调留住。文本和模式仍有临时的长度上限。`string.rep` 的结果也有临时上限；超过则这次调用报错，`pcall` 可以接住，回调继续。`gsub` 的结果缓冲区在每次扩容前计入同一块临时内存预算；各层还没交还的缓冲区加在一起算。超过则这次调用报错，`pcall` 可以接住，回调继续。复制进结果的字节大约每 64 KiB 再对照这 1 秒，到点与钩子一样中止。这四个模式函数同时嵌套最多 8 层，超过则这次调用报错，`pcall` 可以接住。到顶之后，这次调用展开完之前不能再进。`xpcall` 和 `table.sort` 从宿主再进 Lua 时还有重入上限，到顶之后同样要等这次调用展开完。这些字节数和层数仍待定，见「待定」第 2 条，不是产品规则。

`table.sort` 带比较函数时，每次比较都回到 Lua，超时钩子仍然有效。不带比较函数时，比较在 C 里完成；验证程序在元素过多时直接拒绝这次调用。`table.concat`、`string.format`、`string` 的大小写和反转、`utf8` 的长度按文本长度线性完成。`string.format` 的宽度最多两位数字。它们受临时内存上限约束。这些字节数和元素个数不是产品规则。

`timer.every` 的秒数最短是 30。短于 30 则不登记，显示「间隔过短」。`timer.after` 的秒数必须是正数，最短是多少，待定。两者都不是正数则不登记，显示「参数无效」。睡眠或关机期间如何补，待定。

## 组件

第一批组件：文本 `text`、按钮 `button`、计时 `timer`、进度条 `progress`、列表 `list`、输入 `input`、开关 `toggle`。

界面组件 `timer` 显示剩余秒数，由宿主逐秒重画。脚本用 `ui.timer` 设定秒数。组件正在倒数并走到 0 时，宿主调用 `on_timer`。把秒数改成 0，或把倒数停下，都不因此调用。再次设定秒数会换掉上一次倒数。这条回调受 1 秒上限，不受 30 秒刷新下限。显示格式待定。服务 `timer` 只负责定时刷新，不负责把这个组件每秒减一。

每个组件在一个工具里有自己的 id。脚本按 id 改显示，按钮、列表、输入和开关把动作交回脚本。属性和函数见开发说明。

进度条的值按 0 到 1。小于 0 按 0，大于 1 按 1。计时组件小于 0 的秒数按 0。

输入框在中文输入法组合未上屏时，不把未上屏的字交给脚本。上屏之后的文本变化会调用脚本。每个键都调用，还是停一段时间再调用，待定。Enter 是否另有提交，待定。

## 导入

**入口。** 应用页的「导入+」。点它可以选择一个文件夹，或一个 zip。把文件夹或 zip 拖到应用页上，包括拖到「导入+」上，同样开始这一条导入。

**格式。** 文件夹和 zip 都接受。文件夹里要有清单。zip 的根上要有清单，或者 zip 里只有一个顶层文件夹、清单在那个文件夹里。两种都先读清单，再进入确认。示例的写法见开发说明，是一个文件夹里的清单和入口脚本。

**可见内容。** 读到清单后，列出工具名称、一行短说明，以及「服务」里的那些白话句子。同一 id 已经安装时，标明这是更新，并写一句「保留数据」。不能在这一页上改清单，也不能逐条去掉句子。

**动作。** 用户整份接受这些句子之后才安装，或者取消。不能逐条去掉。取消则不安装，数据目录里不留下这份新工具；若是更新，已安装的那一份保持不动。正在等待确认时再拖入或再点「导入+」，不开始第二次。「查看权限」复用这张卡片，没有「确认」，见「应用页」。

安装把副本放进 Lanwork 数据目录。子目录名，待定。程序使用这份副本。不移动、不删除用户原来的文件夹。不写入 MayDolist 的目录。2026-10-15 决定：新导入的工具默认启用。启用状态进入导出，也进入备份。

同一 id 已经安装时，再导入视为更新，必须先经过上面的确认。确认框写「保留数据」。确认后用新副本替换旧副本，同一 id 已有的存储、密钥、窗口位置、大小、贴边和钉住保留。这个工具的悬浮窗如果开着，用新副本和新的授权重新载入这一个窗口，位置、大小、贴边和钉住不变。未确认则不替换，也不重载。从某一张卡片的「更新」选到的包，id 必须是这张卡片的；不是时显示「不是这个工具的更新包」，不打开确认，也不导入。「导入+」和拖入不按某一张卡片核对 id。

**禁止。** 未确认就写入数据目录。导入时读取收纳里的文件内容，或执行工具里的程序。把密钥写进副本。未确认就替换已安装的工具。

**验收。** 点「导入+」选择一个含清单的文件夹，或一个根上有清单的 zip，或把其中一种拖到应用页上，都先看到名称、短说明和白话句子，句子里有申请的域名，没有密钥的值，也不能只勾其中几条。整份确认之后，列表里多出这张卡片。取消时列表不变，数据目录里没有它，原来的文件夹还在。同一 id 再导入时，确认页标明是更新，并有「保留数据」；取消则卡片、存储、密钥、窗口位置、大小、贴边和钉住仍是原来的；确认后卡片用新清单里的名称和短说明，存储、密钥、窗口位置、大小、贴边和钉住仍在。确认时如果这扇悬浮窗开着，窗口仍是原来的位置、大小、贴边和钉住，里面换成新副本。从卡片「更新」选到另一个 id 时，显示「不是这个工具的更新包」，不出现确认页，已安装的工具不变。「导入+」和拖入仍可以导入另一个 id。新导入的工具启用开关是打开的。id 以 `lanwork.` 开头的不安装，并显示「清单无效」。大小写不论，`Lanwork.tool` 同样不安装。清单里写了不认识的服务时不安装。

## 密钥

工具可以在清单里声明若干密钥。每一项有 id 和「填写密钥」里显示的名称。用户在该工具卡片的「⋯」里填写，不在设置页。每一行一个密钥，掩码输入，不回显已保存的值。保存只写入填写了的行；空着的行保持原样。清除删掉这个工具已声明的密钥。值写入 Windows 凭据管理器，按工具 id 和密钥 id 分开，两个工具的同名密钥不混在一起。凭据的目标名字符串，待定。

值不出现在工具文件、导出、备份和日志里。日志沿用现有对密钥形态的删节。错误文字、请求失败的说明和脚本能读到的返回值里都不放密钥原文，也不放已经拼进请求头的值。

脚本不能读取原文，也没有返回原文的函数。它只能在 `http` 请求里用 id 指明附上哪一个。还没填写就附带这个 id 时，不发请求，显示「未填写密钥」。

宿主只看清单里已确认主机返回的正文和响应头。这是尽力检查：密钥被拆开、加密，或用下面没有列出的写法写出来，仍然可能漏过去。

交给脚本之前，在正文和每一个响应头上检查这些形式。任一命中，正文改成空字符串，`ok` 为假，说明是「请求失败」，状态码仍保留。不把响应头放进返回值。命中即整段清空，不做逐段替换。

检查的形式：

- 密钥原文
- `Bearer ` 加原文，以及 `bearer ` 加原文
- 这次实际发出的请求头的值（前缀加原文）
- 上面每一项的标准 Base64 和 URL 安全 Base64，带末尾填充和不带填充。不按编码长短丢弃。短密钥的编码可能只有几个字符，正文里碰巧出现同样的几个字符时也会整段清空。这是宁可误伤，也不漏掉上面承诺的形式。不在写入时另加最短长度：规格没有最短长度，短密钥仍然要能被认出来
- 把正文或响应头里的 `%XX` 按十六进制解码后再找上面的明文和 Base64。`%` 后两位忽略大小写。未保留字节也可以编码，可以只编码其中一部分。连续解码最多四次。原文或解码结果里的 `+` 再按空格看一次

脚本能读到的返回值里没有这些内容。

不回显已保存的值，关掉再打开输入是空的，并且可以清除，已经定了。保存写到一半失败时，已经写上的行生效，并提示「「名称」没有写下」，已经定了。除密钥以外，工具还能声明哪些设置控件，待定。

## 安全模型

1. 工具代码只以沙箱里的 Lua 5.4 运行。宿主不加载工具自带的动态库和可执行文件，不用网页视图。
2. 脚本能碰到的服务就是清单里声明、并且用户已经确认的那些。
3. 未授予的服务不放进这块 Lua 状态。
4. `http` 只向已确认的主机名发送。第一批纳入的是 `https` GET。附带密钥的请求只走 `https`。
5. 密钥只在 Windows 凭据管理器里。工具文件、导出、备份、日志、错误文字和脚本可见的返回值都不含原文，也不含已经附上密钥的请求头。已确认主机的响应若对上「密钥」里列出的形式，正文清空并显示「请求失败」。这是尽力检查。
6. 一个工具的 Lua 状态、存储和密钥与另一个工具分开。
7. 第一批写入只有 `todo.complete` 和 `storage`。完成走现有命令，不能永久删除。便签和其它写入不在第一批。
8. 数据放在 Lanwork 自己的数据目录。不读写 MayDolist 的目录。
9. 搜索框里的字符不创建待办、便签或工具。

1. 清单的版本字段：字段名、当前号、不认识的版本是拒绝还是兼容读取。
2. 脚本的资源限制里尚未定的部分：内存的字节数、CPU、定时器数量、HTTP 并发和超时、存储的条数和单条大小。睡眠或关机期间，已经登记的定时器如何补。`timer.after` 的最短秒数。单次执行最长 1 秒、`pcall` 不能把这次回调留住、`xpcall` 的处理函数也在这 1 秒里、定时刷新（`timer.every`）最短 30 秒、超限报错，都已经定了。超时显示「脚本超时（第 N 行）」，运行失败显示「脚本错误（第 N 行）」，也已经定了。验证程序里另有一块临时内存上限，超过也按超时的方式中止；那个字节数不是产品规则。验证程序里的 `string.find`、`string.match`、`string.gmatch`、`string.gsub` 在匹配过程中按步对照这 1 秒，到点与钩子一样中止。文本和模式另有临时长度上限，`string.rep` 的结果也有临时上限，超过则这次调用报错，`pcall` 可以接住。`gsub` 的结果在每次扩容前计入同一块临时内存预算，各层还没交还的缓冲区加在一起算，超过同样是这次调用的错误，`pcall` 可以接住；复制大约每 64 KiB 再对照这 1 秒。模式函数同时嵌套最多 8 层，到顶之后这次调用展开完之前不能再进。`xpcall` 和 `table.sort` 再进 Lua 时还有重入上限。不带比较函数的 `table.sort` 在元素过多时直接拒绝。这些字节数、层数和元素个数不是产品规则。
