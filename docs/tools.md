# 应用页与悬浮窗工具

本文规定「应用」页、工具悬浮窗外壳，以及工具的可见行为和宿主模型。与 [product.md](product.md) 已经写明的规则冲突时，以 product.md 为准。清单字段、组件和 Lua 调用的写法见 [tool-dev-guide.md](tool-dev-guide.md)。实现状态见 [roadmap.md](roadmap.md)。应用页有代码，未在 Windows 上验收。导入、卸载、更新、查看权限和填写密钥有代码，未在 Windows 上验收。副本这一版在数据目录的 `tools/<工具 id>/`，路径仍待定。悬浮窗外壳可用 `lanwork --float-shell-demo` 打开。宿主在 `crates/toolhost`（包名 `lanwork-toolhost`）。窗口验证程序在 `spikes/toolhost`。

通过标准在 [roadmap.md](roadmap.md)「技术验证」的「工具宿主」。窗口验证程序在 `spikes/toolhost`，不进产品界面。2026-10-15 该项通过。凭据管理器界面待用户用 `lanwork --toolhost-cred write|list|clear` 确认。内存和 CPU 的数字上限仍待定，不宣称已经达到。

2026-10-15 决定。运行时不引入 Vue、Tauri、WebView2，也不用 HTML 或网页视图画工具。工具用宿主自带的 Slint 组件排界面。逻辑用嵌入的 Lua 5.4，库是 `mlua`，放在沙箱里。不引入 cordis 这个库。结构按它的方式：宿主暴露服务，工具在清单里声明要用哪些服务；用户导入时确认；脚本只能调用已经确认的服务。

## 应用页

**入口。** 面板上的「应用」标签。标签顺序是待办、便签、收纳、应用、设置，见 product.md「面板」。便携应用、别名和手动刷新的界面入口仍待定，见 product.md「设置」。

**可见内容。** 已安装工具排成一列扁列表。每一行从左到右是图标、名称、一行短说明、「悬浮」按钮、启用开关和「⋯」。短说明由工具作者写在清单里，这是全局规则 1 的例外。行上除此之外没有介绍和使用步骤。2026-10-15 决定：图标文件是工具文件夹里的 `icon.png`，和清单放在一起。没有这个文件、读不出来或内容不是 PNG 时，用名称去掉首尾空白后的第一个字，不因此拒绝安装。其它图片格式这一版不作为图标。

「导入+」是这一列的最后一行，高度与工具行相同。它是导入入口，没有短说明，也没有启用开关和「⋯」。没有工具时页面上只有这一行，不显示「没有工具」。

**动作。**

| 动作 | 结果 |
| --- | --- |
| 「悬浮」 | 打开该工具的悬浮窗。已经打开时，只把焦点给这个窗口，不出现第二个。启用开关关闭时，这个按钮不可用 |
| 「导入+」 | 开始导入，见「导入」 |
| 「⋯」 | 打开这一行的菜单：「更新」「卸载」「查看权限」。声明了密钥的工具再加「填写密钥」 |
| 「更新」 | 为这一行选择文件夹或 zip。包内 id 不是这一行时，显示「不是这个工具的更新包」，不打开确认，也不导入。id 相符时按「导入」处理 |
| 「卸载」 | 先确认，确认框写「会删除这个工具的存储和密钥。」确认后关掉它的悬浮窗，删除数据目录里的副本、该工具的存储、`tool-windows/<工具 id>.json`，以及它在凭据管理器里的密钥。取消则这些都还在 |
| 「查看权限」 | 打开与导入确认相同的卡片：名称、一行短说明，以及「服务」里的那些白话句子。没有「确认」。关掉这张卡片不改变已经授予的服务 |
| 「填写密钥」 | 只在清单里声明了密钥的工具上出现。弹出与导入确认同一风格的小窗：工具名称，每个密钥一行。左边是清单里的名称，右边是掩码输入，不回显已保存的值，也不显示密钥 id。关掉再打开时输入是空的，不会把上次填的字带到另一个工具。可以保存或清除。保存只把填写了的行写入 Windows 凭据管理器，空着的行保持原样。某一行没有写上时停在这一行，界面写「「名称」没有写下」，不含密钥的值；已经写上的行仍然生效，开着的窗口重载。清除删掉这个工具已声明的密钥，不再询问一次。脚本不能读取原文。已经打开的悬浮窗在保存或清除之后用上新的值。取消则不改 |
| 启用开关 | 每一行都有。关闭时立即停用：关掉悬浮窗，「悬浮」不可用。重启后仍是关闭。再次打开后可以再开悬浮窗 |

**禁止。** 在这一页放功能介绍或使用步骤。用网页视图画这一页。搜索框里的文字不创建工具。未确认就卸载。逐条勾选导入权限。

**验收。** 面板标签是待办、便签、收纳、应用、设置。应用页是一列扁列表，最后一行是「导入+」，高度与工具行相同。没有工具时只显示「导入+」。每一行从左到右是图标、名称、一行短说明、「悬浮」、启用开关和「⋯」。「⋯」里是「更新」「卸载」「查看权限」；这份工具声明了密钥时还有「填写密钥」。有 `icon.png` 时图标用这张图；没有、读不出或不是 PNG 时，用名称去掉首尾空白后的第一个字。点「悬浮」打开该工具的窗口；已经打开时再点，焦点回到这一个窗口。启用开关关闭时「悬浮」点不了，已经打开的窗口马上关掉，重启后开关仍是关闭。点「卸载」后出现确认，上面有「会删除这个工具的存储和密钥。」；取消则工具、存储、密钥和窗口记录都还在；确认后副本、存储、密钥和 `tool-windows/<工具 id>.json` 都没有了，悬浮窗关掉。没有声明密钥的工具不出现「填写密钥」。声明了密钥时，「⋯」里有「填写密钥」：每一行是掩码输入，不回显已保存的值，关掉再打开是空的；保存后空着的行不变，填写了的行写入凭据管理器；某一行没有写上时提示「「名称」没有写下」，已经写上的行仍然生效；清除删掉已声明的密钥。保存或清除之后，已经打开的窗口用上新的值。额度示例没填密钥时窗口上是「未填写密钥」；填上并保存后，这句不再留在已经打开的窗口里。「查看权限」打开的卡片与导入确认相同，没有「确认」，关掉之后授予不变。

## 悬浮窗外壳

2026-10-15 决定，2026-10-16 补定外观和状态。工具的悬浮窗是同一套外壳。外壳负责窗口，工具换上里面的内容和逻辑。

外壳提供这些事：

1. 钉住开着时，始终在其他普通窗口之上。钉住关掉时，是普通窗口层级。没有记下钉住时，按开。
2. 可以拖动。顶部一条细拖动条，高度 28 逻辑像素，与便签悬浮窗的拖动区相同。拖动条右侧是钉住和关闭，各 28×28 逻辑像素，描边和悬停与便签悬浮窗的关闭相同。钉住在关闭左边。
3. 贴边收成把手。规则与便签悬浮窗相同，见 product.md「便签」。那里已经标成待定的项，工具悬浮窗沿用，不在这里另定。贴边后失焦收回与便签相同，钉住开或关都不改变这条。点把手展开，再点把手或失去焦点就收回。
4. 记住位置和大小。关闭后再打开、重启后再打开，用记下的值。不贴边时整扇留在所在显示器的工作区里，规则见 product.md「便签」的「工作区」。贴边时仍按贴边，不拉回工作区。可以拖边改大小。最小 200×120 逻辑像素，与便签相同。
5. 钉住。钉住和位置、大小、贴边、叠页一起记住。
6. 叠页。拖到便签、收纳或待办悬浮窗上，松手时重叠超过一半，就合成一叠，规则见 product.md「便签」的「叠页」。各页共用这一份位置和大小。展开并且至少两页时，彩色圆点在窗口下方靠左。钉住关掉时，这些圆点和这扇窗口同一层。左右方向键翻页；内容区占用这两个键时留给内容。这一版的工具行不占用左右键。
7. 来源行。展开时拖动条下面一行是「应用 · 工具名」。工具名取清单名称里第一个去掉首尾空白后还有字的行。名称没有可见字符时，这一行只显示「应用」。收成把手时不显示这一行。

窗口不点击穿透。不出现在任务栏。失去焦点后的半透明磨砂与便签悬浮窗相同，见 product.md 全局规则 6。面板收起或失焦时，这个窗口不关闭。关闭窗口只关窗口，不卸载工具。

没有记下位置和大小时，出现在主屏工作区的右下角，与工作区右缘和下缘各留 24 逻辑像素。默认大小用工具声明的尺寸；清单没有声明时是 320×360 逻辑像素。声明小于最小尺寸时，用最小尺寸。

内容区由清单里的组件画出，宿主用自带的 Slint 组件绘制。组件按清单顺序从上到下排成一列。嵌套、分栏和网格，待定。拖动条、贴边把手、钉住和关闭画在内容区外面。

每个工具一份记录，在数据目录的 `tool-windows/<工具 id>.json`。id 的规则与数据文件的 id 相同。不写进工具文件夹，也不是安装副本的路径；安装副本的路径仍待定。记录里有 `schemaVersion`、可选的 `floatWindow`（`x`、`y`、`width`、`height`）、可选的 `floatDock`、可选的 `floatPinned`、可选的 `floatStack`（`id`、`index`、`current`，与便签同一结构），以及 `open`。`floatPinned` 缺了按开，写出的 `false` 是明确关掉。`open` 为真表示退出时这个窗口开着。不在叠里时，下次启动再打开。关掉窗口写成假，叠页成员仍留在 `floatStack` 里。已经叠在一起时，重启后按 product.md「便签」的叠页打开当前页，其余页不另开窗口。`floatWindow` 这个字段在、但坐标读不出时，不把它当成没有位置：记下的贴边仍用，并且这次自动打开不覆盖原文件。叠页写回位置和成员时也留着原文件。缺了 `floatStack`、`id` 是空白，或形状不是对象，都当成没有叠页，其余字段照常打开。

窗口位置、大小、贴边、钉住和叠页进入导出，也进入备份，字段相同。`open` 只在这份窗口记录里，用来重启后重新打开，不进入导出和备份。`tool-windows/<工具 id>.json` 进入导出白名单和备份白名单；包里的这份把 `open` 写成没有，恢复后窗口不因此自动打开。叠页随这份记录走。更换数据目录时按磁盘上的原文件复制，`open` 仍在。

便签悬浮窗、收纳悬浮窗和待办悬浮窗用同一套外壳画拖动条、关闭、来源行、贴边把手和叠页圆点，里面只换内容。这三扇没有钉住按钮，始终在最上层。工具窗口用同一套来源行和叠页，并保留钉住。钉住按钮由外壳的开关控制，只在工具窗口上打开。位置仍记在原来的便签文件、分组文件和 `todo-float.json` 里，不改成 `tool-windows/`。工具的位置、贴边、钉住和叠页记在 `tool-windows/<工具 id>.json`。旧的 `floatPinned` 在便签、收纳、待办上仍能读入并丢掉，不写回。

调试时可以用隐藏命令 `lanwork --float-shell-demo` 打开一个内容是「示例」的外壳窗口。这不是产品入口，也不是已安装的工具。记录 id 是 `lanwork.float-shell-demo`。已经有 Lanwork 在运行时，这条命令不会打开窗口，要先退出。

**禁止。** 用 HTML、网页视图或 WebView2 画内容区。在外壳上放说明文字。来源行是这一页的名称，见 product.md「便签」的「来源行」。

## 工具包

一个工具是一个文件夹。文件夹里有一份 TOML 清单，以及清单 `entry` 指向的一个 Lua 入口脚本。界面布局写在这份清单里，不另放界面描述文件。字段见开发说明。可选的 `icon.png` 和清单放在一起，见「应用页」。清单不因此增加字段；不认识的字段仍拒绝安装。

逻辑由宿主用 `mlua` 嵌入 Lua 5.4 执行。每个工具一块独立的 Lua 状态。一个工具不能调用另一个工具的服务，也不能读到另一个工具的存储或密钥。

脚本在沙箱里。标准库只放入开发说明列出的那一部分。没有 `io`、`os`、`package`、`debug`。不能加载工具文件夹以外的文件，不能加载本机动态库，不能启动进程。宿主不执行工具文件夹里的可执行文件。协程不放入：超时钩子按 Lua 线程安装，协程是另一条线程，钩子管不到。`require` 和多个 Lua 文件是否允许，待定。入口脚本以外的 `.lua` 文件不执行。

工具 id 不能以 `lanwork.` 开头。比较忽略大小写，`Lanwork.tool` 和 `LANWORK.x` 也不行。这是保留前缀。以它开头的不安装，并显示「清单无效」。日志里的说明仍是「id 不能以 lanwork. 开头」。

清单里出现本文和开发说明没有列出的字段、不认识的组件或不认识的服务时，不安装，并显示「清单无效」。版本字段的名字、当前号，以及不认识的版本是拒绝还是兼容读取，待定。在这确定之前，清单不写版本字段；写了会因不认识的字段被拒绝。

## 服务

第一批服务如下。工具在清单的 `services` 里声明。界面上每条是一句白话，不显示内部标识。

| 服务 | 界面句子 | 允许 |
| --- | --- | --- |
| `timer` | 定时刷新 | 按脚本登记的秒数，到期后调用脚本给出的函数。到点之前不调用。间隔最短 30 秒 |
| `notify` | 发送通知 | 发一条系统通知。安静时段内不弹出；时段结束后，错过的多条按产品规格「待办」合并补发 |
| `storage` | 保存这个工具自己的数据 | 按键读写这个工具自己的文本。不存放密钥 |
| `todo.read` | 读取你的待办 | 读取待办，含已完成和当前标记，不含回收站 |
| `todo.complete` | 完成你的待办 | 走现有的完成。带周期的按产品规格生成下一次。不能取消完成、新建、改标题或删除 |
| `http` | 每个域名一句「访问 <主机名>」。允许提交时，每个域名再加一句「向 <主机> 提交数据」。每个固定请求头一句「请求头 <名称>: <值>」 | 只向清单里列出、且用户确认过的主机名发请求。可以发 `https` 的 GET。清单写了 `post = true` 时，还可以向这些主机 POST JSON |
| `secret` | 每个密钥一句。没有前缀时是「使用你填写的 <名称>，请求头 <名称>」。写了前缀再接「，前缀 <前缀>」，前缀按清单逐字显示 | 用户在工具设置里填写。值放进 Windows 凭据管理器。脚本不能读取原文，也不能另选请求头 |

`http` 不另显示一句「联网」。确认时看到的是逐条主机名。允许提交时，同一台主机紧接着一句「向 <主机> 提交数据」，主机名用清单里的写法。每个固定请求头单独一行，名称和值都写出来，沿用清单里的大小写，中间是「请求头 」、半角冒号和一个空格。`secret` 确认时出现名称、请求头名字和前缀，不出现值，也不出现密钥 id。

GET 一直可以发。额度示例用的就是 `https` GET。POST 只有清单里 `[http]` 的 `post` 为真才发送，并且对 `domains` 里的每一台都允许，不按主机再拆开。没写 `post` 或写成假时，POST 不发送，显示「不在范围内」。GET 和 POST 以外的方法不发送，也显示「不在范围内」。不附带密钥的明文 `http` 不发送，已经定了。窗口显示「不允许明文 http」。附带密钥时只允许 `https`；不是 `https` 就不发送，显示「地址无效」，避免密钥走明文。`http` 与 `https` 以外的协议不发送，显示「地址无效」。

主机名与清单里某一条忽略大小写相等才发送。`api.example.com` 只等于它自己，不包含 `example.com`，也不包含下一级主机名。路径不另做限制。主机名不在已确认的清单里时不发送，显示「域名未允许」。重定向一律不跟随，已经定了，同一主机名之内也不跟随。不读取 `Location`，也不发第二次请求。状态码是 3xx 时显示「请求失败」。主机名写成 IP、或在域名里写端口、路径、通配符时，清单无效。IP 是否允许仍待定。

一次请求可以附上多个已声明的密钥，最多 8 个，每个密钥进清单里为它写死的那一个请求头。脚本只用密钥的 id 指明附上哪几个。请求头名字和值前面的字，例如 `Bearer `，写在清单的该项上，确认页能看到。脚本如果还写了请求头或前缀，必须和清单一致，否则不发送，显示「地址无效」。发出去的名字和前缀始终用清单里的。宿主拼好之后发出。脚本读不到拼好的头，也读不到密钥原文。同一请求里两个密钥不能进同一个头（名字忽略大小写）。主机名必须已确认。发出请求的那次脚本调用不等待网络；连接和读取在宿主侧完成，有单独的等待上限，秒数仍待定。

固定请求头写在清单的 `[http]` 里，不由脚本临时添加。没有声明 `User-Agent` 时，发出的请求仍带 `User-Agent: Lanwork`。声明了就把这个值换成清单里的值，只留一条。`Accept` 没声明时仍是 `*/*`。`Host`（主机名，不带端口）、`Connection: close`，以及 POST 时的 `Content-Type: application/json` 和 `Content-Length`，由宿主写入。名字比较忽略大小写。拒绝 `Host`、`Cookie`、`Content-Length`、`Content-Type`、`Transfer-Encoding`、`Connection`，以及 `Keep-Alive`、`Proxy-Authenticate`、`Proxy-Authorization`、`Proxy-Connection`、`TE`、`Trailer`、`Upgrade`。固定请求头不能与密钥声明的请求头重名，固定请求头之间也不能重名。名字只含 ASCII 字母、数字和 `-`，不能以 `-` 开头或结尾，最长 64。值是可打印 ASCII（空格到 `~`），不能含回车、换行和控制字符，去掉首尾空白后还要有字，最长 512。前缀同样只含可打印 ASCII，可以是空字符串，最长 128。固定请求头最多 16 条。不合这些规则的清单不安装，界面仍是「清单无效」，日志里写明是哪一条。固定请求头的值会出现在确认页和授权记录里，不要把密钥写在这里。

授予 `todo.read` 时，待办变更之后宿主调用脚本的 `on_todos_changed`。脚本再自己读。这个回调不写入。

`todo.complete` 走现有待办命令。与本机同时修改同一条时不覆盖，悬浮窗显示「待办保存冲突」。脚本不接触修订号。宿主使用当前已保存的修订号。本机还有未写盘的修改时，同样不覆盖。

`notify.send` 一律遵守安静时段：安静时段内不弹出；时段结束后，错过的多条按产品规格「待办」合并成一条，可以展开查看。

`storage` 的文本不写入工具文件夹，进入导出和备份。单条大小和键的数量，待定。密钥不进 `storage`。

一次 Lua 回调从进入到返回最长 1 秒。超过则中止这次调用。脚本用 `pcall` 接住这次中止后，钩子仍会在后续检查里继续报错，这次回调不能接着跑完。`xpcall` 的处理函数由宿主在被保护函数返回之后调用，超时钩子仍然开着；处理函数里的死循环同样中止。悬浮窗显示「脚本超时（第 N 行）」，N 是行号，不含密钥。已经登记、尚未触发的定时器还在。宿主重画计时组件不占这 1 秒，也不算定时刷新。等网络也不占这 1 秒：套接字不在这条 Lua 调用里。

`string.find`、`string.match`、`string.gmatch`、`string.gsub` 的模式匹配在宿主里按 Lua 5.4 的规则执行。匹配过程中计数，大约每 4096 步对照这次回调的 1 秒截止时间。到点则与钩子一样中止，窗口显示「脚本超时（第 N 行）」，`pcall` 不能把这次回调留住。文本和模式仍有临时的长度上限。`string.rep` 的结果也有临时上限；超过则这次调用报错，`pcall` 可以接住，回调继续。`gsub` 的结果缓冲区在每次扩容前计入同一块临时内存预算；各层还没交还的缓冲区加在一起算。超过则这次调用报错，`pcall` 可以接住，回调继续。复制进结果的字节大约每 64 KiB 再对照这 1 秒，到点与钩子一样中止。这四个模式函数同时嵌套最多 8 层，超过则这次调用报错，`pcall` 可以接住。到顶之后，这次调用展开完之前不能再进。`xpcall` 和 `table.sort` 从宿主再进 Lua 时还有重入上限，到顶之后同样要等这次调用展开完。这些字节数和层数仍待定，见「待定」第 2 条，不是产品规则。

`table.sort` 带比较函数时，每次比较都回到 Lua，超时钩子仍然有效。不带比较函数时，比较在 C 里完成；验证程序在元素过多时直接拒绝这次调用。`table.concat`、`string.format`、`string` 的大小写和反转、`utf8` 的长度按文本长度线性完成。`string.format` 的宽度最多两位数字。它们受临时内存上限约束。这些字节数和元素个数不是产品规则。

`timer.every` 的秒数最短是 30。短于 30 则不登记，显示「间隔过短」。`timer.after` 的秒数必须是正数，最短是多少，待定。两者都不是正数则不登记，显示「参数无效」。睡眠或关机期间如何补，待定。

## 密钥

工具可以在清单里声明若干密钥。每一项有 id、「填写密钥」里显示的名称，以及要放进的请求头。前缀可以不写。用户在该工具这一行的「⋯」里填写，不在设置页。每一行一个密钥，掩码输入，不回显已保存的值。保存只写入填写了的行；空着的行保持原样。清除删掉这个工具已声明的密钥。值写入 Windows 凭据管理器，按工具 id 和密钥 id 分开，两个工具的同名密钥不混在一起。凭据的目标名字符串，待定。

值不出现在工具文件、导出、备份和日志里。日志沿用现有对密钥形态的删节。错误文字、请求失败的说明和脚本能读到的返回值里都不放密钥原文，也不放已经拼进请求头的值。

脚本不能读取原文，也没有返回原文的函数。它只能在 `http` 请求里用 id 指明附上哪几个。一次请求里的每个密钥进清单为它声明的请求头。还没填写就附带这个 id 时，不发请求，显示「未填写密钥」。其中一个没填，这一次整份都不发。清单里没写请求头的密钥不安装，界面是「清单无效」。

宿主只看清单里已确认主机返回的正文和响应头。这是尽力检查：密钥被拆开、加密，或用下面没有列出的写法写出来，仍然可能漏过去。

交给脚本之前，在正文和每一个响应头上检查这些形式。任一命中，正文改成空字符串，`ok` 为假，说明是「请求失败」，状态码仍保留。不把响应头放进返回值。命中即整段清空，不做逐段替换。

检查的形式：

- 密钥原文
- `Bearer ` 加原文，以及 `bearer ` 加原文
- 这次实际发出的请求头的值（前缀加原文）
- 上面每一项的标准 Base64 和 URL 安全 Base64，带末尾填充和不带填充。不按编码长短丢弃。短密钥的编码可能只有几个字符，正文里碰巧出现同样的几个字符时也会整段清空。这是宁可误伤，也不漏掉上面承诺的形式。不在写入时另加最短长度：规格没有最短长度，短密钥仍然要能被认出来
- 把正文或响应头里的 `%XX` 按十六进制解码后再找上面的明文和 Base64。`%` 后两位忽略大小写。未保留字节也可以编码，可以只编码其中一部分。连续解码最多四次。原文或解码结果里的 `+` 再按空格看一次

脚本能读到的返回值里没有这些内容。

不回显已保存的值，关掉再打开输入是空的，并且可以清除，已经定了。保存写到一半失败时，已经写上的行生效，并提示「「名称」没有写下」，已经定了。除密钥以外，工具还能声明哪些设置控件，待定。

## 插件登录

工具可以声明 `[[login]]`，自己写明登录文件、要读的字段、放进哪个请求头、怎样判断过期、向哪个地址发什么请求，以及把响应里的哪些字段交给脚本。这不是 `services` 里的一项。用量这一类请求写成这种描述。用量来源写在清单的 `[[login]]` 里。清单里出现 `usage` 时不安装，界面是「清单无效」，日志写明不认识的字段。

确认页在密钥句子之后、通知之前，按清单顺序写每一项。第一句是「读取本机文件 ~/路径 中的 名称，发往 地址」。名称是该项的 `label`。方法是 POST 时，把「发往」写成「提交到」。接着每个固定请求头一行「请求头 名称: 值」。每个登录字段一行：没有前缀时是「请求头 名称」，写了前缀再接「，前缀 前缀」，前缀按清单逐字显示，末尾空格也留着。最后一行「交给脚本：名字、名字」，名字用顿号分开。多了一项，或已经有的那一项里文件、字段、请求头、前缀、过期、请求或提取有任何一处改动，都要再确认。少了一项不算扩大。备份和导出的那一次确认用同一套句子。授权记下整份描述。

宿主只读登录文件，不写、不刷新、不修改。脚本调用 `login.fetch`，只拿到清单点名的字段。登录文件里的值、令牌和原始正文不进脚本、工具存储、日志、错误文字和调试输出。

`file` 相对用户家目录，只接受以 `.json` 结尾的路径。可以写成 `~/.codex/auth.json`，宿主去掉开头的 `~/` 或 `~\`，确认页再补回 `~/`。家目录先用 `USERPROFILE`，没有或是空的才用 `HOME`，而且必须是绝对路径。两个都没有，或者不是绝对路径，窗口显示「登录已过期」，不发请求，也不读当前工作目录。插件描述不能用环境变量另换目录。

下面这些路径不安装，界面是「清单无效」：含 `..` 或空段；以 `/` 或 `\` 开头；绝对路径、盘符、UNC；路径里出现 `:`；任何一段叫 `.ssh` 或 `.gnupg`；`AppData` 之后出现一段 `User Data`；`Firefox` 之后出现一段 `Profiles`；连续的 `AppData\Roaming\Microsoft\Credentials` 或同样的前三段再加 `Protect`；连续的 `Documents\Lanwork`。比较忽略大小写。

读的时候只打开一次。先按家目录拼出路径，打开这个文件，从这次打开的句柄取出最终路径，再对这条路径做家目录、拒绝位置、`.json` 和数据目录检查，然后从同一个句柄读取，上限 256 KiB。不再按名字打开第二次。Windows 上这次打开允许别的程序同时读和写，不带打开重解析点的标志：当时已经存在的符号链接和 junction 会跟着走，句柄落在目标文件上；之后换到路径上的重解析点，这次读取不会再跟着走。最终路径用规范化名字，8.3 短名会展开成原名。硬链接数大于 1 的文件拒绝，这个数目也从句柄上读。解析之后仍必须在家目录里面。解析进上面这些位置，或者解析进 Lanwork 正在使用的数据目录，都当作没有登录，显示「登录已过期」，不发请求。数据目录就是家目录时，家目录下的登录文件都在数据目录里，因此全部拒绝。文件大于 256 KiB 同样如此。

`fields` 至少一项，最多 8 项。每一项有 `name`、`path`、`header`，`prefix` 可以不写。`header` 和 `prefix` 的规则与密钥请求头相同。同一项里的请求头不能重名，也不能和这次请求的固定请求头重名。`path` 用点号分开对象的键，用 `[下标]` 取数组。下标从 0 起，不允许前导零，最大 4096。键里不能有 `.`、`[`、`]` 和控制字符。可选的 `key_prefix` 用来挑 JSON 顶层的键：键等于这个前缀，或者后面紧跟 `/`、`:`。有多项时取键的字典序最小、字段都能读到、并且还没过期的那一个。`path` 相对这个对象。同一个前缀的字段用同一个键。读到的值必须是非空的可打印 ASCII 字符串，否则当作没有登录。

`expires` 可以不写。写了的话，`format` 是 `epoch_s`、`epoch_ms`、`rfc3339` 或 `jwt_exp`。前三种要有 `path`，值按这个单位解释，不自动把秒和毫秒对调。`rfc3339` 只认 RFC3339 字符串。`jwt_exp` 要有 `field`，指向某个字段的名字，从那段 JWT 的载荷取 `exp`，不校验签名。JWT 缺段、解码不了、载荷不是 JSON 或没有数字 `exp`，都当作过期，不因此崩溃。`path` 上可以再写 `key_prefix`。当前时间已经到达或超过过期时间，或文件、字段不在，窗口显示「登录已过期」，不发请求。

`request.method` 是大写的 GET 或 POST。`url` 必须是 https，主机名、路径和查询都写死在清单里，不能带用户名、密码、端口或片段。主机名必须出现在这个工具的 `domains` 里，所以要同时声明 `http`。脚本不能改方法、地址、路径、查询或请求头。POST 必须带静态 JSON 正文，最长 64 KiB。GET 不能带正文。这不打开脚本自己的 POST。固定请求头的规则与 `[http]` 相同，最多 16 条。没写 `User-Agent` 时仍是 `Lanwork`，没写 `Accept` 时仍是 `*/*`。只走 https，不跟随重定向。状态码 3xx 显示「请求失败」。401 或 403 显示「登录已过期」，不解析正文。等待和正文 1 MiB 上限与 `http` 相同。

`extract` 至少一项，最多 32 项。每一项有 `name`、`path`、`type`。`type` 是 `number`、`string` 或 `bool`。宿主解析 JSON，只把这些名字放进返回值。路径不在或值是 `null` 时，这个名字不出现。类型对不上，或一个都没取到，整份是「数据无效」。字符串去掉控制字符，最长 128 个字符。交给脚本之前，宿主把每个字符串提取，以及按声明顺序拼起来的全部字符串提取，拿去和登录文件里的值比对。要比的值是放进请求头的每个字段值，再加上文件里其余每一个不少于 8 字节的字符串，不设条数上限。比对是尽力检查，形式与密钥回显相同：原文、实际发出的请求头值、标准 Base64 和 URL 安全 Base64（带填充和不带填充）、百分号编码、十六进制。比对前先去掉 Unicode 格式字符（Cf，含零宽字符）和空白。任一处对上，整份就是「数据无效」。数字和布尔不参与这道检查。

脚本写成 `login.fetch("id", function(result) end)`。这次调用不等待网络。`result.ok` 为真时有 `values`。为假时有 `error`，没有 `values`。id 不是这个工具声明过的，马上回调「未授权」，也不看缓存。同一个工具、同一个 id、同一份描述，60 秒内再取，返回上次的结果，不再读文件、不再发请求。成功和失败都这样。缓存键带有整份描述的指纹，描述改过之后不会把上次的结果交回去。先核对声明，再查缓存。另一个工具同名的 id 不会拿到这份缓存。

用这种描述做成的示例：`examples/chatgpt-usage` 分两行显示 5 小时和每周的百分数与重置时刻；`examples/claude-usage` 分两行显示 5 小时和 7 天；`examples/grok-usage` 一行显示额度百分数和重置时刻。Claude 的订阅令牌按 Anthropic 的条款只用于 Claude Code 和 claude.ai，使用该示例由用户自行承担风险，见该目录的 README。Grok 的键前缀和 `expires_at` 格式见该目录的 README。

## 安全模型

1. 工具代码只以沙箱里的 Lua 5.4 运行。宿主不加载工具自带的动态库和可执行文件，不用网页视图。
2. 脚本能碰到的服务就是清单里声明、并且用户已经确认的那些。
3. 未授予的服务不放进这块 Lua 状态。
4. `http` 只向已确认的主机名发送。可以发 `https` GET；清单允许提交时还可以 POST JSON。附带密钥的请求只走 `https`。固定请求头和密钥头都在确认范围内，脚本不能另选密钥头，也不能另加请求头。
5. 密钥只在 Windows 凭据管理器里。工具文件、导出、备份、日志、错误文字和脚本可见的返回值都不含原文，也不含已经附上密钥的请求头。已确认主机的响应若对上「密钥」里列出的形式，正文清空并显示「请求失败」。这是尽力检查。
6. 插件登录由清单写明文件、字段、过期和请求，脚本只能拿到清单点名的字段。令牌、账号、网址、原始正文和登录文件里的值不进脚本、工具存储、日志、错误文字和调试输出。字符串提取里的回显检查是尽力检查，数字和布尔不参与。宿主不修改这些登录文件。
7. 一个工具的 Lua 状态、存储和密钥与另一个工具分开。
8. 第一批写入只有 `todo.complete` 和 `storage`。完成走现有命令，不能永久删除。便签和其它写入不在第一批。
9. 数据放在 Lanwork 自己的数据目录。不读写 MayDolist 的目录。登录用量读的是各应用自己的登录文件，不写进 Lanwork 的数据目录，也不修改那些文件。
10. 搜索框里的字符不创建待办、便签或工具。

## 验收

应用页的工具排成一列扁列表，「导入+」是最后一行，高度与工具行相同。没有工具时只显示「导入+」。每一行从左到右是图标、名称、一行短说明、「悬浮」、启用开关和「⋯」。导入文件夹或 zip，以及拖到应用页上，都先看到白话句子、主机名、固定请求头、密钥请求头、插件登录的文件路径和发往地址，以及提交那一句，整份确认后才出现这一行；取消则不出现，也不能只接受其中几条。同一 id 再导入要先确认，确认框有「保留数据」，句子里包括新的密钥、改过的密钥请求头或前缀、固定请求头、主机名、提交权限和改过的插件登录，确认后才换成新副本，存储、密钥和窗口位置仍在；开着的窗口在原位重载。从这一行的「更新」选到另一个 id 时显示「不是这个工具的更新包」，不继续导入。卸载要先确认，确认框有「会删除这个工具的存储和密钥。」，确认后副本、存储、密钥和 `tool-windows/<工具 id>.json` 都没有了。每一行都有启用开关；关闭时悬浮窗马上关掉，「悬浮」不可用，重启后仍是关闭。每一行的「⋯」是「更新」「卸载」「查看权限」；声明了密钥时还有「填写密钥」。有 `icon.png` 时这一行用这张图；没有、读不出或不是 PNG 时，用名称去掉首尾空白后的第一个字。新导入的工具启用开关是打开的。点「悬浮」打开该工具的窗口；已经打开时，焦点回到这一个窗口。

额度示例的窗口里有一行文本和一条进度条。打开时请求一次，之后每 5 分钟再请求。请求的主机名就是确认过的那一条。没填密钥时不发请求，窗口上是「未填写密钥」。在「填写密钥」里保存之后，已经打开的窗口不再显示这句。脚本侧拿不到密钥。服务端把密钥回显在正文或响应头里时，只要对上「密钥」列出的形式（含百分号编码的未保留字节、只编码一部分、十六进制大小写混合），脚本看到的正文是空的，窗口上是「请求失败」。导出和备份里都有这个工具的副本、启用状态、窗口位置、大小、贴边、钉住、叠页和存储，没有密钥。入口脚本或清单与本机同 id 副本内容不同时，恢复清除该工具在凭据管理器里的密钥；内容相同则保留。跨机器恢复后，窗口上是「未填写密钥」。日志里也没有密钥。安静时段内，这个工具的通知不弹出。

外壳钉住开着时始终在其他普通窗口之上，关掉后是普通窗口层级。可以拖动，贴边收成把手，记住位置、大小、贴边、钉住和叠页。展开时来源行是「应用 · 工具名」，名称没有可见字符时只显示「应用」，收成把手时不显示。可以和便签、收纳、待办悬浮窗落在同一叠。脚本不每秒被调用；计时组件自己倒数。登记短于 30 秒的定时刷新会被拒绝。一次回调超过 1 秒时，即使脚本用 `pcall` 接住，窗口仍显示「脚本超时（第 N 行）」。`xpcall` 的处理函数超时同样如此。脚本运行失败显示「脚本错误（第 N 行）」。

导出再导入之前，概览列出每个工具的名称和与清单一致的权限句子，含固定请求头的名称和值、密钥的请求头和前缀、插件登录的文件路径、发往地址、请求头和交给脚本的字段，以及「向 <主机> 提交数据」；不合格的写「不会恢复」和原因。取消则不写入，确认后才写入，授权按清单重新生成。备份再恢复走同一份确认。更换数据目录不确认。导出再导入之后，工具副本、启用状态、窗口的位置、大小、贴边、钉住、叠页和该工具的存储还在。备份再恢复也一样。密钥不在导出里，也不在备份里。跨机器恢复后，窗口上是「未填写密钥」。入口脚本和清单与本机副本内容相同的，本机密钥仍在。

上面几项里，应用页和导入是产品验收，还没有在 Windows 上执行。应用页已有代码，未在 Windows 上验收。导入、卸载、更新、查看权限和填写密钥有代码，未在 Windows 上验收。副本这一版在 `tools/<工具 id>/`，路径仍待定。导出、备份和更换数据目录有代码，未在 Windows 上验收。启用状态在 `tool-enabled.json`，进入导出和备份。悬浮窗外壳已有代码，可用 `lanwork --float-shell-demo` 打开。2026-10-16 用户在 Windows 上手测外壳通过（main `e0a797d`）。技术验证「工具宿主」已通过，见 [roadmap.md](roadmap.md)。凭据管理器界面待用户用 `lanwork --toolhost-cred write|list|clear` 确认。

## 待定
