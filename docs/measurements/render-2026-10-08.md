## 采样怎么偏离协议

`lanwork-sample` 按 1 秒间隔采了约 60 秒，不是 300 秒。窗口没有收起。场景 B 在滚动。没有 `EmptyWorkingSet`。第一行之前的基线不写入 CSV，所以 60 秒请求得到 57 或 58 行，首尾间隔约 59 秒。

FemtoVG 场景 A 用的是还没把 `PDH_CALC_NEGATIVE_VALUE` 当成可重试状态的采样器，那一次 `stop` 仍是 `duration`。其余七次用的是会重试该状态的采样器。重试不改 Private Bytes 和工作集的读法。

有效样本不是 100 个延迟样本。这一项按架构只记录内存、工作集和字形，不产生 P95。

## 三个纯色条件

纯色值是这次测量用的对照色，不是产品规格。浅色 `#F3F3F3`，暗色 `#202020`。产品只要求与主题一致。

系统设置：开始时 `EnableTransparency` 为 1，`AppsUseLightTheme` 为 1。测试里把 `EnableTransparency` 写成 0，确认标签变成 `transparency-off` 后又写回 1。写回后的注册表值是 1。`AppsUseLightTheme` 没有改。过程在 `render/system-changes.txt`。电池节电没有改。

1. 透明效果关闭，含变更通知。同一进程里，注册表改成 0 之后标签变为 `transparency-off`，约 350 毫秒后的截图中心是 243,243,243。写回 1 之后标签回到 `acrylic`，backdrop 读回 3，截图中心回到 139,139,139。截图：`render/shots/transparency/01-acrylic.png`、`02-transparency-off.png`、`03-acrylic.png`。没有为这件事显示提示。人仍要看窗口是不是立刻变成纯色，而不是只看这个延迟一拍的截图。
2. 节电。未测。当时接电源，`Win32_Battery.BatteryStatus` 为 2，电量 96%。程序读到的 `battery_saver` 为 false。电源通知的子类装上了（`subclass_installed` 为 true），但没有观察到节电状态变化。手动步骤见文末。
3. 透明渲染失败。注入一块不透明黑之后，`self_test_detected` 为 true，随后屏幕像素为 243,243,243，`self_test_solid` 为 true。截图 `render/shots/self-test/01-render-failed.png` 中心也是 243,243,243。这只说明检测管线能看见我们铺上去的黑，并退回纯色。四种渲染器的正式场景截图都不是黑底。不能把注入试验写成「渲染器透明失败已经发生」。检测不到真实失败时，这一条不能算通过，也没有从通过标准里删掉。

关透明效果时如果把纯色矩形自己的不透明快照再当成失败，窗口会粘在纯色上，即使透明效果已经打开。测量程序现在在透明效果关闭、节电或 build 低于 22621 时不再把快照不透明记成渲染失败。

## 本机暂定倾向

只针对这块 Intel UHD，不能写成架构里的选定结果。第二台独立 GPU 还没有数。

Private Bytes 的差距大于这几次采样里的抖动：软件渲染约 5 MiB，Skia 软件约 26 MiB，FemtoVG 约 57 MiB，Skia OpenGL 约 75 MiB。空面板上，软件渲染和 Skia 软件的唤醒大约每秒 1 次以下；两条 OpenGL 路径大约每秒 60 次。二进制体积上软件渲染和 FemtoVG 都在 10 MiB 左右，两条 Skia 路径都约 18.7 MiB。

若只按这台机器的内存和空闲唤醒，软件渲染更合适。若人看过截图后认为软件渲染的汉字不可接受，下一候选是 Skia 软件，而不是 Skia OpenGL。这个倾向不写进 architecture.md「运行时」，roadmap 两行也不标通过。

## 人还要做的事

1. 在第二台有独立 GPU 的 Windows 11 上，用同一套 release 命令各采场景 A 和 B 约 60 秒，并看亚克力。这台只有 Intel UHD，两台机器的条件不能勾。
2. 看着窗口，不要只看 BitBlt 截图：四种渲染器的亚克力是不是霜化背景而不是一块灰；客户区有没有黑底；汉字「中文字形：测量亚克力渲染器 繁體簡体 ggyy 0OIl1」的笔画和英文 ggyy、0OIl1 是否可接受。截图在 `docs/measurements/render/shots/`。
3. 系统主题切换。本次没有改 `AppsUseLightTheme`。请在设置里切换应用明暗，看亚克力和纯色是否跟着主题，并且没有提示。`--theme dark` 只改这个测量窗口的暗色属性，截图 `shots/theme-dark-in-app/01-acrylic.png` 不是系统主题切换。
4. 节电。本次没有打开节能模式。接电源时可以：设置 → 系统 → 电源和电池 → 节能模式 → 立即打开。然后运行下面的命令，看同一进程的状态文件从 `acrylic` 变成 `battery-saver`，窗口变成纯色且没有提示；关掉节能模式后，不重启进程应回到亚克力。测完确认节能模式已关。

```text
cargo run -p lanwork-render-spike --release --no-default-features --features femtovg -- --scene a --exit-after-secs 30 --status-out battery.json --shot-dir shots-battery
```

5. 透明效果。本次已经改过并恢复：`EnableTransparency` 最终为 1。若要再看一次「立刻变成纯色」，在设置里关闭透明效果，窗口应变成纯色；打开后应回到亚克力。注册表路径是 `HKCU\Software\Microsoft\Windows\CurrentVersion\Themes\Personalize` 的 `EnableTransparency`。
6. 品红参考窗只说明 BitBlt 没有把客户区拍成品红：`shots/reference-magenta/01-acrylic.png`。人要看窗口后面放一块亮色时，亚克力是否真的混进那块颜色。
